# Тестовый набор CPU v1

Синтетический набор для повторяемых замеров CPU ONNX и CPU OpenVINO.
Это искусственные сцены, а не запись регистратора и не набор для оценки точности.

## Состав

| Видео | Размер | Длительность | Нагрузка сцены |
| --- | --- | --- | --- |
| videos/empty_720p.mp4 | 1280×720 | 6 секунд, 25 FPS | Без знаков |
| videos/sparse_720p.mp4 | 1280×720 | 6 секунд, 25 FPS | Два нарисованных знака |
| videos/dense_1080p.mp4 | 1920×1080 | 6 секунд, 25 FPS | Восемь нарисованных знаков |

Все три ролика проверены полным декодированием: по 150 кадров.

- `frames/`: 18 PNG, по одному кадру на секунду каждого ролика.
- `crops/`: 9 вырезок трёх искусственных знаков в размерах 32, 64 и 128 пикселей.
- `annotations.json`: координаты нарисованных объектов на сохранённых кадрах. Названия synthetic_kind не являются метками классов моделей проекта.
- `synthetic.gpx`: искусственный маршрут, начинающийся 2026-01-01 00:00:00 UTC. Каждый ролик соответствует началу этого маршрута; GPS в видео не встроен. Для полного пайплайна потребуется явно согласовать начало времени видео и GPX.
- `manifest.json`: параметры генерации, версии библиотек и SHA-256 исходных файлов.

## Как сравнивать производительность

1. Использовать одни и те же файлы, версии весов, размеры входа, пороги и количество потоков CPU в обоих режимах. Загруженные модели должны иметь эквивалентные веса и точность вычислений.
2. Проверять фактически выбранный backend: скрытый переход на PyTorch делает сравнение недействительным. В этой копии проекта обнаружены указатели Git LFS вместо весов; их нужно загрузить и получить экспорты ONNX/OpenVINO до измерений.
3. Замер загрузки и компиляции модели записывать отдельно. Перед измерением выполнить прогрев, затем минимум пять повторений каждого сценария. Для коротких видео повторять обработку кадров до суммарного времени не менее 30 секунд.
4. Отдельно измерять декодирование, детектор на кадрах, классификаторы на вырезках и полный пайплайн. Сравнивать медиану и p95 времени кадра, FPS, память и количество результатов. Не считать чтение PNG частью чистого времени модели.
5. Сохранять результаты распознавания до и после оптимизации на одинаковых входах. Изменения классов, координат и уверенности проверять отдельно от скорости.

Нарисованные знаки могут вообще не распознаваться детектором. Поэтому «плотный» ролик не гарантирует нагрузку классификаторов; для их измерения предназначены отдельные вырезки. Нулевая разница результатов на этом наборе не доказывает сохранение качества на настоящих дорогах. OCR, трекинг и геопривязка также требуют реальных записей для содержательной оценки.

## Повторная генерация

Из корня проекта:

```powershell
.venv/Scripts/python.exe scripts/benchmarks/prepare_cpu_data.py --output benchmark_data/cpu_synthetic_v2
```

Генератор не перезаписывает существующий каталог. Начальное значение генератора случайных чисел фиксировано; побайтовая воспроизводимость видео зависит от версии OpenCV и кодека. Для сравнения использовать уже созданный набор и его контрольные суммы.
