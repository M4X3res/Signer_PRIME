# Подготовка и публикация релиза

1. Увеличьте `version.json`: опубликованные версии не перезаписываются.
2. Запустите `scripts\build\prepare_release.bat` из любого каталога.
3. Проверьте результат в `release/`. Скрипт сам компилирует `SignerInstaller-<version>.exe` через Inno Setup 6.
4. Запустите `scripts\build\upload_release.bat -Draft` (или напрямую `upload_release.ps1 -Draft`), чтобы оставить проверенный релиз черновиком, либо без `-Draft` для публикации.

Подготовка сохраняет предыдущую сборку в `release_baselines/<version>/`, её инвентарь — в `release_inventories/`, прежние архивы — в `release_history/`. Не удаляйте эти каталоги до прекращения поддержки старых версий. Для пользователей старых установщиков без установленного манифеста нужна точная база их версии; нельзя подставлять произвольную сборку с тем же номером.

Все 18 YOLO-моделей принудительно экспортируются в ONNX/OpenVINO. OCR-веса проверяются по контрольным суммам EasyOCR и включаются в приложение. При отсутствии локального кеша скрипт подготовки OCR скачивает веса на сборочной машине; готовая программа OCR-веса не скачивает. Frozen-приложение не запускает pip. Кеши инференса находятся в пользовательском каталоге `Signer/model_cache`, вне установленного дистрибутива.

Проверка собранного EXE выполняет инференс всех моделей на PyTorch CPU, ONNX и OpenVINO, а при доступной CUDA — и на GPU; отдельно проверяет OCR. Результат передаётся через JSON-файл, поэтому проверка работает и для оконной сборки без stdout. Откат на другой backend считается ошибкой.

Манифест создаётся **до** архива и устанавливается вместе с программой. При наличии сохранённой базы выпускается дельта-архив; полное обновление также использует сохранённый или установленный инвентарь. Пользовательские результаты, логи и кеши в инвентарь релиза не добавляются.

Загрузчик сначала проверяет локальные версии, состав и SHA-256, затем загружает файлы в черновик. Перед публикацией он сверяет размер и серверный SHA-256 каждого файла. Ошибка оставляет релиз черновиком; уже опубликованный релиз изменять нельзя. Архивы, манифест, дельты и установщик публикуются вместе.

Обычная установка обновляется без повышения прав. Если каталог установки защищён, загрузки размещаются в пользовательском `Signer/updates/<id>`, а обновлятор запрашивает UAC перед закрытием приложения. Отмена UAC оставляет приложение запущенным.

Для повторного запуска прерванной сборки используется `.release-build-pending.json`; после успешной подготовки маркер удаляется. Не создавайте этот файл вручную для обхода проверки версии.

Завершение упаковки после успешной проверки уже собранного EXE: `python scripts/build/finish_release.py`. Этот шаг не заменяет проверку моделей. Многотомный архив проверяется командой 7-Zip `t`; чрезмерно большая дельта не публикуется, используется полное обновление.

Можно публиковать проверенный выпуск из другого каталога: `scripts/build/upload_release.ps1 -ReleaseDirectory .release_validation/release -Draft`. Проверка локальных файлов обязательна и в этом режиме.
