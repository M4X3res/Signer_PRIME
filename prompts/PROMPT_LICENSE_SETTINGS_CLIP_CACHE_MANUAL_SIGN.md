## Задача 2 — Кэш видео-клипов карты: отдельная папка + очистка

### Контекст
`server/map_server.py::api_video_clip()` транскодирует короткие WebM-клипы вокруг знака (и полное видео) и кэширует результат **прямо рядом с исходным видеофайлом**:

```python
video_dir = os.path.dirname(video_path)
video_base = os.path.splitext(os.path.basename(video_path))[0]
cache_filename = f"{video_base}_clip_{int(round(start))}_{int(duration)}.webm"   # или f"{video_base}_full.webm"
cache_path = os.path.join(video_dir, cache_filename)
```

Проблемы: замусоривает папку с исходным видео (плюс может быть на read-only/сетевом диске), не пере­используется между запусками, никогда не удаляется — `_full.webm` может быть по размеру сравним с оригиналом.

### Что сделать

1. Заведи константу/хелпер (например, в начале `server/map_server.py`):
   ```python
   CLIP_CACHE_DIRNAME = ".signer_clip_cache"

   def _get_clip_cache_dir(video_path: str) -> str:
       video_dir = os.path.dirname(video_path)
       cache_dir = os.path.join(video_dir, CLIP_CACHE_DIRNAME)
       os.makedirs(cache_dir, exist_ok=True)
       return cache_dir
   ```
   Используй эту функцию в `api_video_clip()` вместо прямого `video_dir` при формировании `cache_path` — и для короткого клипа, и для `_full.webm`.

2. Добавь функцию очистки кэша клипов:
   ```python
   def clear_clip_cache(video_dir: str) -> tuple[int, int]:
       """Удаляет папку кэша клипов для указанной директории с видео.
       Возвращает (кол-во удалённых файлов, освобождено байт)."""
   ```
   Реализуй безопасное удаление (проверка что папка называется именно `CLIP_CACHE_DIRNAME`, чтобы случайно не удалить что-то не то).

3. Автоматическая очистка **устаревшего** кэша при старте новой обработки:
   - В `ui/widgets/dashboard_page.py::_on_video_changed()` (или в `processing/processing_controller.py::start()`) при выборе новой папки с видео — вызови очистку кэша клипов **для предыдущей** выбранной папки видео (если она отличается от новой), чтобы не копить мусор между разными сессиями/видео. Если это усложняет код — как минимум добавь очистку при **завершении обработки** (`ui/main_window.py::_on_save_finished()` или `_on_finish()`), т.к. именно тогда пользователь обычно переходит смотреть карту и генерируется много клипов.
   - Не удаляй кэш, если пользователь **прямо сейчас** просматривает карту с клипами того же видео (простая эвристика: не делай авто-очистку во время активного показа карты, только при смене источника видео/после завершения обработки — не при каждом клике).

4. Добавь Flask-роут для ручной очистки из UI карты (или из Настроек — выбери то, что логичнее интегрируется, но роут в любом случае должен быть):
   ```python
   @app.route("/api/clear_clip_cache", methods=["POST"])
   def api_clear_clip_cache():
       ...
   ```
   Возвращает JSON `{"ok": true, "files_removed": N, "bytes_freed": N}` или `{"error": "..."}`.

5. UI-кнопка ручной очистки:
   - Добавь кнопку **«🗑 Очистить кэш видео»** в `templates/map.html` в topbar (`#topbar`), рядом с существующими кнопками (`По треку`, `Трек`, `Live`, `GeoJSON`). По клику — `fetch(`${API}/clear_clip_cache`, {method: "POST"})`, покажи `toast()` с результатом («Освобождено X МБ» или «Кэш уже пуст»).
   - **ИЛИ** (выбери один вариант, не оба, чтобы не плодить дублирующийся UI) — кнопку в `ui/widgets/settings_page.py` в новой или существующей технической группе (например, рядом с группой «Диагностика системы (расширенная)»), которая тоже дергает тот же Flask-эндпоинт через `requests`, либо напрямую вызывает `clear_clip_cache()` из `server/map_server.py`, если Flask ещё не запущен.
   - Предпочтительный вариант — **кнопка на карте** (`map.html`), т.к. пользователь видит клипы именно там и понимает, зачем их чистить.

6. Убедись, что после переноса пути кэша существующая логика проверки `if os.path.exists(cache_path): return send_file(...)` (cache hit) продолжает работать без изменений — просто путь теперь внутри подпапки.

### Тесты
Добавь `tests/check_clip_cache.py` (без pytest): читает `server/map_server.py` и проверяет:
- наличие `CLIP_CACHE_DIRNAME` и что старый паттерн `os.path.join(video_dir, cache_filename)` (без подпапки) больше не используется для `cache_path` в `api_video_clip`;
- наличие функции очистки кэша и роута `/api/clear_clip_cache`.

## Задача 3 — Ручное добавление знака на карте

### Контекст
Модель могла не распознать реальный знак. Сейчас на карте (`templates/map.html`) можно только **редактировать тип** существующего распознанного знака (`PATCH /api/sign/<id>`) и **удалять** его (`DELETE /api/sign/<id>`), но **нет способа добавить новый знак**, которого не было в GeoJSON вообще.

Серверная часть уже частично готова: `server/map_server.py::api_sign_create()` (`POST /api/sign`) создаёт новый `Feature` в GeoJSON по `{type, lat, lon, azimuth, description}`. Но:
- Поле `"left"` в этом роуте сейчас захардкожено как строка-маркер `"manually_added"` — это **несовместимо** с остальным проектом, где `"left"` — это `str(bool)` (`"True"`/`"False"`), см. `core/final_handler.py::_build_feature()` и `templates/map.html::parseSide()` / `filterSide` в `renderMarkers()`. Из-за этого текущий код ломает фильтр «Лево/Право» и отображение стороны для вручную добавленных знаков.

### Что сделать

#### 3.1. Исправить сервер (`server/map_server.py::api_sign_create`)
- Принимай из тела запроса необязательное поле `"is_left"` (bool, по умолчанию `False`).
- Записывай `feature["properties"]["left"] = str(bool(is_left))` — консистентно с остальным пайплайном.
- Добавь отдельный флаг происхождения знака, не переиспользуя `"left"`:
  `feature["properties"]["manually_added"] = True`.
- Остальную логику (генерация `id`, `code`, `conf_cnn`/`conf_total` = 1.0, `length` = 1, текст для знаков с надписью) оставь как есть.
- Провалидируй: `lat`/`lon` — числа в разумном диапазоне (широта [-90,90], долгота [-180,180]) — если уже не провалидировано, добавь.

#### 3.2. Front-end (`templates/map.html`)

1. Добавь кнопку **«＋ Добавить знак»** в `#topbar`, рядом с существующими кнопками управления картой.

2. Реализуй «режим размещения»:
   - По клику на кнопку — включается `placementMode = true`, кнопка визуально становится активной (класс `accent`, текст меняется на «✕ Отменить размещение»), курсор карты меняется на crosshair (`document.getElementById('map').style.cursor = 'crosshair'`).
   - Пока `placementMode === true`, следующий клик по карте (`map.on('click', ...)`) — а не по существующему маркеру — берёт координаты клика (`e.latlng.lat`, `e.latlng.lng`) и:
     - выключает `placementMode`, возвращает курсор и текст кнопки в исходное состояние;
     - открывает панель добавления знака (см. п. 3.3) с уже подставленными координатами.
   - Esc должен отменять режим размещения (добавь обработчик `keydown`).
   - Пока `placementMode === true`, клики по существующим маркерам знаков должны по-прежнему работать как раньше (выбор знака) — не блокируй их, срабатывание на пустой области карты и на маркере — разные события (`map click` vs `marker click`), это уже разделено в Leaflet по умолчанию, просто убедись, что не добавляешь конфликтующих обработчиков.

3. Панель добавления знака — переиспользуй существующую разметку `#detail-content`/`#edit-section` по максимуму (не создавай полностью параллельную панель с нуля, чтобы не дублировать стили):

     - `#detail-img-row` скрывается или показывает placeholder-иконку;
     - `#detail-fields` (время/видео/азимут/сторона) скрыты или заменены на редактируемые поля создания: азимут (числовой инпут, по умолчанию `0`), сторона (два переключаемых чипа/радио «Слева»/«Справа», по умолчанию «Справа»);
     - `#edit-type` (уже заполняется из `/api/sign_types`) используется для выбора типа — обязательное поле;
     - `#edit-desc`/`#edit-desc-row` работают как раньше (показываются для знаков с текстом);

   - Вызови `renderMarkers()`, `selectSign(result.id)`, `toast("Знак добавлен", "ok")`.
   - Закрой панель создания, верни её в обычный режим отображения деталей.
   - При ошибке — `toast(`Ошибка добавления: ${err.message}`, "err")`, панель создания остаётся открытой, чтобы не терять введённые данные.

5. Кнопка «Отмена» в панели создания — просто закрывает панель/возвращает в обычный режим без запроса к серверу.

#### 3.3. Проверка обратной совместимости в остальных потребителях GeoJSON
- `ui/widgets/error_editor_page.py::SignRecord` — убедись, что запись без `absolute_frame_numbers`/`pixel_coordinates_x` и т.п. (у вручную добавленного знака этих полей нет) не приводит к исключению. Это не обязательно, но желательно для UX.

## Порядок работы

1. Изучи все перечисленные файлы целиком перед правками.
2. Реализуй задачи по очереди: 1 → 2 → 3 (они не зависят друг от друга, но так проще проверять).
3. После каждой задачи — запусти/добавь соответствующий лёгкий regression-тест и проверь его вручную (`python tests/check_*.py`).
4. Не забудь: любые новые пользовательские строки — на русском, в стиле остального проекта.
5. В конце — кратко перечисли все изменённые/созданные файлы и что именно в них поменялось (как в существующих `*_REPORT.md` файлах проекта, но без лишнего пафоса — только по делу).
