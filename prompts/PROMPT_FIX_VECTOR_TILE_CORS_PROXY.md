# PROMPT: Векторные тайлы скачиваются напрямую, но не открываются в приложении — включить серверный прокси и починить подстановку токена

## Контекст (что уже известно, не передиагностируй с нуля)

Пользователь настроил векторные тайлы (`map_tile_type = "vector"`) со
следующим URL (пример, токен реальный но приведён как есть из репорта):

```
http://api.maps.by/api/vectorTile/VectorTileServer/tile/9/163/291.pbf?token=$2a$10$HjQGLFcbSxufG2tXIF0LnuXIONY9WSxISngU/S.PFvf.TcVM/7EXS*$2a$10$HjQGLFcbSxufG2tXIF0Lnuq3.mkcSkvRlVbXCw/jcTwxLNjJZYOy6&
```

**Установленный факт (это меняет диагноз из предыдущего промпта
`PROMPT_FIX_VECTOR_TILE_LOADING.md`):** если открыть/скачать этот URL
напрямую (адресная строка браузера, `curl`, "скачать файл") — `.pbf`
файл успешно скачивается. Это означает:

- URL, путь, z/x/y и токен **валидны и рабочие** — сервер отвечает `200`
  и отдаёт реальные бинарные данные протобуфа. Задача 3c (битый/склеенный
  токен) из предыдущего промпта **не актуальна как причина отказа** —
  хотя валидация на "подозрительные" `*`/пробелы всё ещё стоит оставить
  как защиту от опечаток в будущем, она не объясняет текущий баг.
- Прямое скачивание — это **top-level navigation / отдельный HTTP-клиент**,
  который не подчиняется CORS. Загрузка того же URL из `fetch()`/`XHR`
  внутри `QWebEngineView` (то есть именно так, как это делает
  `L.vectorGrid.protobuf(cfg.tile_url, ...)` в `templates/map.html`) —
  это cross-origin запрос со страницы `http://127.0.0.1:3000/`, который
  браузерный движок (Chromium/QtWebEngine) блокирует по CORS, если
  `api.maps.by` не возвращает заголовок `Access-Control-Allow-Origin`.
  У большинства ArcGIS/Esri `VectorTileServer` инстансов такого заголовка
  нет по умолчанию.
- **Рабочая гипотеза №1 (наиболее вероятная): это CORS.** Обычный
  Esri `VectorTileServer` формат — это валидный Mapbox Vector Tile
  (protobuf), так что после устранения CORS `Leaflet.VectorGrid.protobuf`
  с высокой вероятностью отрисует тайлы штатно с уже существующим
  generic-стилем `{ '*': genericStyle }`.
- **Рабочая гипотеза №2 (проверить, если №1 не решает проблему
  полностью):** несовпадение схемы/имён слоёв внутри Esri-тайла, которое
  требует явного списка слоёв вместо `'*'`.

Твоя задача — реализовать серверный прокси как **основной путь** загрузки
векторных тайлов (не "опционально, если Задача 1 подтвердит"), потому что
факт из этого промпта уже эквивалентен подтверждению CORS-гипотезы для
Esri-подобных серверов без выделенного шага диагностики. При этом ты всё
равно обязан проверить в DevTools, что до фикса запрос из
`QWebEngineView` реально падал по CORS (см. Задача 0) — чтобы задокументировать
факт, а не гадать.

## КРИТИЧЕСКИЕ ОГРАНИЧЕНИЯ

- Не менять пайплайн обработки видео/знаков: `core/`, `processing/`,
  `licensing/`.
- Не ломать растровый режим (`map_tile_type = "raster"`) — дефолт,
  должен продолжать работать без прокси и без изменений в поведении.
- Не хардкодить в код токен/URL этого конкретного пользователя. Прокси
  должен работать для любого корректно введённого URL векторных тайлов
  (Esri, обычный MVT, с токеном или без).
- Порт карты (3000), архитектура Flask/SocketIO/ServerThread не меняются.
- Токен пользователя — чувствительные данные: не логировать его в
  открытом виде на уровне `INFO`/`ERROR` (маскировать в логах, например
  показывать только первые/последние 4 символа), не отправлять его на
  фронтенд в `/api/map_config`, если используется режим прокси (см.
  Задачу 2).

## Задача 0 — Быстрая контрольная диагностика (не пропускать, но не растягивать)

1. В `MapPage` открой карту с текущим (нерабочим) векторным URL, открой
   DevTools (кнопка "⬡ В браузере" → обычный Chrome, или встроенный
   inspector QWebEngine) и на вкладке Network найди попытку запроса к
   `api.maps.by`. Зафиксируй: ушёл ли запрос вообще, и если да — есть ли
   в консоли текст вида `blocked by CORS policy` / `No
   'Access-Control-Allow-Origin' header`.
2. Одной строкой зафиксируй результат в комментарии в
   `server/map_server.py` рядом с новым прокси-роутом (см. Задачу 1):
   что именно было в консоли до фикса. Это не должно занимать больше
   одной итерации — если факт CORS подтвердился, сразу переходи к
   реализации.

## Задача 1 — Реализовать и включить по умолчанию серверный прокси векторных тайлов

Добавить в `server/map_server.py` роут прокси (эндпоинт уже частично
описан в предыдущем промпте — доведи его до рабочего состояния, эта
версия ниже фиксит конкретные проблемы прошлой заготовки):

```python
@app.route("/api/vector_tile_proxy/<int:z>/<int:x>/<int:y>")
def api_vector_tile_proxy(z, x, y):
    """
    Прокси для векторных тайлов — обходит CORS-блокировку, т.к. большинство
    ArcGIS/Esri VectorTileServer инстансов не отдают
    Access-Control-Allow-Origin, а QWebEngineView (как и любой браузер)
    блокирует fetch/XHR с другого origin без этого заголовка.

    Формирует upstream URL из настроек (map_tile_url с подставленными
    {z}/{x}/{y}), сохраняя query string (токен!) как есть, и пробрасывает
    ответ как application/x-protobuf с корректным Access-Control-Allow-Origin.
    """
    from configs.settings import get_app_settings
    import requests as req

    settings = get_app_settings()
    if settings.map_tile_type != "vector":
        return jsonify({"error": "vector tiles not configured"}), 400

    upstream_url = _build_upstream_tile_url(settings.map_tile_url, z, x, y)

    masked = _mask_token_for_log(upstream_url)
    logger.info(f"[vector_tile_proxy] GET {masked}")

    try:
        resp = req.get(upstream_url, timeout=10)
        resp.raise_for_status()
        return Response(
            resp.content,
            mimetype="application/x-protobuf",
            headers={
                "Access-Control-Allow-Origin": "*",
                "Cache-Control": "public, max-age=86400",
            },
        )
    except req.exceptions.HTTPError as e:
        status = e.response.status_code if e.response is not None else 502
        logger.warning(f"[vector_tile_proxy] Upstream HTTP {status} for {masked}")
        return jsonify({"error": f"Upstream HTTP {status}"}), status
    except req.exceptions.Timeout:
        logger.warning(f"[vector_tile_proxy] Timeout for {masked}")
        return jsonify({"error": "Upstream timeout"}), 504
    except Exception as e:
        logger.warning(f"[vector_tile_proxy] {e} for {masked}")
        return jsonify({"error": str(e)}), 502
```

Реализуй вспомогательные функции:

1. **`_build_upstream_tile_url(template, z, x, y)`** — критично: не делать
   тупую подстановку `{z}`/`{x}`/`{y}` только в путь и терять query string.
   Используй `template.replace("{z}", str(z)).replace("{x}", str(x)).replace("{y}", str(y))`,
   но **обязательно сохрани весь остаток строки, включая `?token=...&...`**,
   если он присутствует в `map_tile_url`. Проверь на реальном примере из
   этого промпта, что итоговый URL после подстановки идентичен рабочему
   (тому, что скачивается напрямую), кроме z/x/y. Если в `map_tile_url`
   встречается `{s}` (поддомен), подставляй `"a"` как и раньше.
2. **`_mask_token_for_log(url)`** — маскирует любое значение параметра
   `token=` в URL для безопасного логирования (например,
   `token=****EXS` — оставить только последние 3-4 символа). Использовать
   при каждом логировании upstream URL в этом роуте и нигде не печатать
   URL целиком с токеном на уровне `INFO`/`WARNING`/`ERROR`.

## Задача 2 — Включить прокси по умолчанию для vector-режима в `/api/map_config`

Сейчас в `/api/map_config` есть заготовка `use_proxy = False` (захардкожена
выключенной). Поменяй логику:

1. Добавь в `AppSettings` (`configs/settings.py`) новое поле
   `map_tile_use_proxy: bool = True` (дефолт `True` для новых
   инсталляций — то есть прокси включён "из коробки" для vector-режима,
   так как это устраняет самый частый источник провала — CORS). Растровый
   режим прокси не использует независимо от этого флага.
2. В `/api/map_config` (`server/map_server.py`):
   - Если `settings.map_tile_type == "vector"` и `settings.map_tile_use_proxy`
     истинно → отдавай клиенту `tile_url = "/api/vector_tile_proxy/{z}/{x}/{y}"`
     (относительный путь, тот же origin что и страница карты — значит
     сам этот запрос уже никогда не будет блокирован CORS) и
     `"use_proxy": True`.
   - Иначе (растровый режим, или vector с явно выключенным прокси в
     настройках — оставь такую возможность для случаев, когда сервер сам
     умеет отдавать `Access-Control-Allow-Origin` и прокси не нужен) —
     поведение как раньше, прямой `settings.map_tile_url`.
   - **Не включай токен и полный `map_tile_url` в JSON-ответ клиенту**,
     когда используется прокси — фронтенду для этого режима нужен только
     относительный путь прокси, а токен остаётся только на сервере
     (читается из `AppSettings` внутри самого роута прокси). Это заодно
     убирает утечку токена в DOM/консоль браузера.
3. В `ui/widgets/settings_page.py` добавь в группу "Карта" переключатель
   (`ToggleButton`, по аналогии с остальными) "Прокси для векторных
   тайлов" с подсказкой в духе: "Обходит блокировку CORS у большинства
   ArcGIS/Esri серверов векторных тайлов, проксируя запросы через
   локальный сервер. Отключайте только если ваш провайдер тайлов сам
   поддерживает CORS." Подключи в `_collect_settings()`/`_reset()`
   аналогично остальным toggle-полям этой группы.

## Задача 3 — `templates/map.html`: убрать хардкод протокола под прямой URL, если пришёл прокси

`loadTileLayer()` уже строит `L.vectorGrid.protobuf(cfg.tile_url, ...)` —
раз сервер теперь может отдавать относительный путь прокси, а не полный
внешний URL, дополнительных изменений в подстановке плейсхолдеров
`{z}/{x}/{y}` в самом JS обычно не требуется (Leaflet.VectorGrid одинаково
работает и с относительными, и с абсолютными URL-шаблонами) — но:

1. Убедись, что `tileerror`/`tileload` логи (добавленные, предположительно,
   в рамках предыдущего промпта) печатают итоговый URL тайла — если нет,
   добавь, чтобы можно было визуально сверить, что запрос теперь идёт на
   `http://127.0.0.1:3000/api/vector_tile_proxy/...`, а не напрямую на
   `api.maps.by`.
2. Если `cfg.use_proxy === true`, замени текст диагностического
   HEAD-запроса тестового тайла (если он был добавлен в предыдущем
   промпте для раннего обнаружения ошибок) так, чтобы он тоже бил в
   прокси-путь, а не в `cfg.tile_url` напрямую с ручной подстановкой
   z/x/y — иначе тестовый запрос будет проверять не то, что реально
   использует Leaflet.

## Задача 4 — Если после прокси тайлы всё ещё не рисуются (гипотеза №2)

Только если после Задач 1–3 тайлы по-прежнему не отображаются, но
`tileload`-события в консоли говорят, что тайлы физически скачиваются
(нет `tileerror`, Network показывает `200` через прокси) — переходи к
проверке схемы слоёв:

1. Запроси (curl/браузер) `http://api.maps.by/api/vectorTile/VectorTileServer/resources/styles/root.json`
   или `.../VectorTileServer` (без `/tile/...`) — Esri обычно отдаёт JSON
   с полем `layers`, где перечислены реальные имена слоёв.
2. Если такие имена найдены и они специфичны (не `water`/`roads`, а
   что-то вроде `Land`, `Boundary Line`), замени `vectorTileLayerStyles`
   в `templates/map.html` с одного generic `{ '*': genericStyle }` на
   явную карту `{ realLayerName1: style1, realLayerName2: style2, '*': genericStyle }`,
   сохранив `'*'` как fallback для неперечисленных слоёв.
3. Если и это не помогает — зафиксируй как задокументированное
   ограничение в комментарии кода и в ответе пользователю (`toast`),
   что конкретно этот Esri-сервис не полностью совместим с
   `Leaflet.VectorGrid` (например, использует нестандартную кодировку
   геометрии), и предложи пользователю использовать растровый режим
   подложки как рабочую альтернативу.

## Задача 5 — Регресс

После всех правок обязательно проверить:

1. `map_tile_type = "raster"` (дефолт) по-прежнему работает без изменений,
   прокси не участвует.
2. Векторный режим с включённым прокси (дефолт) реально отображает
   тайлы `api.maps.by` из примера пользователя на карте (не только "нет
   ошибки в консоли" — визуально должна появиться подложка, отличная от
   пустого фона).
3. Векторный режим с выключенным прокси (для гипотетического провайдера,
   который сам поддерживает CORS) по-прежнему пытается грузить тайлы
   напрямую, как раньше — переключатель реально на что-то влияет, а не
   игнорируется.
4. Токен пользователя не появляется в открытом виде ни в `/api/map_config`
   ответе (проверить через DevTools → Network → Response), ни в
   `roadscan.log`/консоли сервера.
5. Не затронуты `core/`, `processing/`, `licensing/`, порт 3000.

## Критерии приёмки

1. Тайлы с URL вида из этого промпта (`api.maps.by/.../VectorTileServer/tile/{z}/{y}/{x}.pbf?token=...`)
   реально отображаются на карте в `QWebEngineView`, а не только скачиваются
   напрямую в браузере.
2. Причина (CORS) подтверждена диагностикой из Задачи 0 и зафиксирована
   комментарием в коде, а не оставлена как непроверенное предположение.
3. Прокси включён по умолчанию для vector-режима, но выключаем через UI.
4. Токен нигде не логируется и не уходит на фронтенд в открытом виде при
   использовании прокси.
5. Растровый режим и ранее рабочие пути не регрессировали.
