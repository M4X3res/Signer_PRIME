# Промпт для AI-агента (V2): предыдущий фикс кнопок не сработал — доделать точно

Скопируй весь текст ниже и отдай агенту. Это **повторная** попытка — первая (см.
`PROMPT_FIX_BUTTON_LAYOUT_ISSUES.md`) не решила проблему до конца: кнопки навигации
и кнопка сортировки в редакторе ошибок **до сих пор съезжают/обрезаются/вылезают за
границы панели**. Ниже — точная причина и конкретный фикс без права на догадки.

---

## Фактическое подтверждение, что фикс не сработал

**Скрин A (nav bar):** кнопки "← Пред." и "След. →" разной ширины, панель списка
знаков наезжает на правую детальную панель — виден обрезанный текст "СТОРОН"/"Левая"
и "1:19 · GC" из соседней панели. Это означает, что **левая панель физически шире,
чем ей выделено сплиттером**, потому что сумма минимальных ширин виджетов внутри
`nav_bar` больше, чем `panel.minimumWidth()`/выделенное место — Qt не сжимает
дочерние виджеты ниже их `minimumSizeHint()`, поэтому сплиттер "трещит" и панель
наезжает на соседнюю.

**Скрин B (сортировка):** кнопка с одной иконкой "↑" отрисована отдельным
"плавающим" прямоугольником, частично залезающим за пределы своей строки/панели
(видна тёмная область рядом — это уже чужая зона за краем панели). Причина та же:
у кнопки остался явный `setFixedWidth(...)`/`setMinimumWidth(...)`, который в сумме
с `_filter_combo` не влезает в реальную ширину панели.

**Вывод:** решение "просто уменьшить текст кнопки" или "перенести в два ряда" —
недостаточно, если у виджетов остаются **фиксированные минимальные ширины**,
сумма которых не проверена арифметически против реальной ширины панели. Нужно
убрать вообще все фиксированные ширины у этих элементов и считать бюджет ширины
математически, либо явно увеличить минимальную ширину панели/сплиттера так, чтобы
она гарантированно вмещала сумму минимумов.

## Файл: `ui/widgets/error_editor_page.py`, метод `_build_list_panel`

### Шаг 1 — убрать ВСЕ фиксированные ширины у nav-кнопок

Найди текущий код (после первой правки он может выглядеть чуть иначе, но суть та же):
```python
self._btn_prev = QPushButton("← Пред.")
self._btn_next = QPushButton("След. →")
for btn in (self._btn_prev, self._btn_next):
    btn.setObjectName("BtnSecondary")
    btn.setFixedWidth(...)   # <-- ЛЮБОЕ фиксированное число — убрать целиком
    btn.setSizePolicy(...)   # <-- заменить
    btn.setCursor(Qt.CursorShape.PointingHandCursor)
```

Замени на:
```python
self._btn_prev = QPushButton("← Пред.")
self._btn_next = QPushButton("След. →")
for btn in (self._btn_prev, self._btn_next):
    btn.setObjectName("BtnSecondary")
    btn.setSizePolicy(QSizePolicy.Policy.Expanding, QSizePolicy.Policy.Fixed)
    btn.setMinimumWidth(0)          # явно снять любой унаследованный минимум
    btn.setCursor(Qt.CursorShape.PointingHandCursor)
```

Метку счётчика сделай узкой и с приоритетом сжатия ниже, чем у кнопок:
```python
self._lbl_nav = QLabel("—")
self._lbl_nav.setObjectName("EditorNavLabel")
self._lbl_nav.setAlignment(Qt.AlignmentFlag.AlignCenter)
self._lbl_nav.setFixedWidth(48)      # фиксированная, но МАЛЕНЬКАЯ ширина под "12 / 34"
self._lbl_nav.setSizePolicy(QSizePolicy.Policy.Fixed, QSizePolicy.Policy.Fixed)
```

И задай `stretch factor` явно при добавлении в layout, чтобы кнопки делили
оставшееся пространство поровну, а метка не растягивалась:
```python
nb_lay.addWidget(self._btn_prev, 1)   # stretch=1
nb_lay.addWidget(self._lbl_nav,  0)   # stretch=0 — не растягивается
nb_lay.addWidget(self._btn_next, 1)   # stretch=1
```

Уменьши отступы, если панель узкая:
```python
nb_lay.setContentsMargins(6, 0, 6, 0)
nb_lay.setSpacing(4)
```

**Почему это работает:** у кнопок теперь нет `minimumSizeHint`, требующего 130px —
Qt может сжать их сколько угодно (`Expanding` не задаёт минимум сам по себе, а
`setMinimumWidth(0)` явно снимает любой унаследованный от QSS минимум типа
`min-width: 120px` у `#BtnSecondary`). Если текст "← Пред." не влезает при очень
узкой панели — это ожидаемо и нормально (Qt сам подрежет через elide, либо текст
останется видимым частично), но панель **больше не будет вылезать за пределы
сплиттера**, потому что теперь ничего не требует минимума больше, чем реально
доступно.

### Шаг 2 — QSS проверка: убедись, что `#BtnSecondary` не навязывает `min-width`

Файл `ui/themes/modern_styles.py`, правило:
```css
#BtnSecondary {
    ...
    min-width: 120px;
    min-height: 36px;
}
```
Это правило **действует на ВСЕ** кнопки с `objectName == "BtnSecondary"`, включая
`_btn_prev`/`_btn_next`/`_sort_dir_btn`. Именно `min-width: 120px` в QSS — наиболее
вероятная реальная причина того, что `setMinimumWidth(0)` в Python не помогает: QSS
`min-width` имеет приоритет и переопределяет программные попытки сузить кнопку.

**Обязательно сделай одно из двух:**
- **Вариант А (рекомендуется):** задай этим конкретным трём кнопкам **отдельный
  objectName**, не участвующий в правиле `#BtnSecondary` с `min-width: 120px`,
  например `"BtnNavCompact"`, и добавь в `modern_styles.py` копию стиля
  `#BtnSecondary`, но **без** `min-width` (оставь только `min-height: 36px`,
  `border-radius`, цвета, `padding: 6px 10px` вместо `10px 16px`):
  ```python
  self._btn_prev.setObjectName("BtnNavCompact")
  self._btn_next.setObjectName("BtnNavCompact")
  self._sort_dir_btn.setObjectName("BtnNavCompact")
  ```
  ```css
  #BtnNavCompact {
      background-color: transparent;
      color: {t['text_primary']};
      border: 1.5px solid {t['border_default']};
      border-radius: 8px;
      padding: 6px 10px;
      font-size: 12px;
      font-weight: 500;
      min-height: 32px;
      /* без min-width */
  }
  #BtnNavCompact:hover {
      background-color: {t['bg_hover']};
      border-color: {t['border_strong']};
  }
  ```
- **Вариант Б (быстрее, но грязнее):** переопредели через `setStyleSheet(...)`
  локально на инстансе кнопки с `min-width: 0px;`, что имеет более высокий
  приоритет, чем глобальный `#BtnSecondary` QSS — но вариант А чище и правильнее
  для проекта, используй его.

## Шаг 3 — та же проблема (QSS `min-width: 120px`) для кнопки сортировки

Файл: `ui/widgets/error_editor_page.py`, там где создаётся `self._sort_dir_btn`.

Текущий код (после первой попытки, судя по скрину — иконка `↑`, но кнопка всё
равно вылезает):
```python
self._sort_dir_btn = QPushButton("↑")
self._sort_dir_btn.setObjectName("BtnSecondary")   # <-- вот источник проблемы
self._sort_dir_btn.setCheckable(True)
self._sort_dir_btn.setFixedHeight(28)
self._sort_dir_btn.setMinimumWidth(140)            # <-- если ещё осталось — убрать
```

Замени на:
```python
self._sort_dir_btn = QPushButton("↑")
self._sort_dir_btn.setObjectName("BtnNavCompact")   # см. Шаг 2, вариант А
self._sort_dir_btn.setCheckable(True)
self._sort_dir_btn.setFixedSize(36, 32)             # компактный квадрат под иконку
self._sort_dir_btn.setToolTip("По возрастанию")
```
И в обработчике переключения (`_on_sort_direction_toggled` или как он называется)
обновляй именно `setToolTip(...)`, а не текст кнопки — кнопка должна оставаться
маленьким квадратом с одной иконкой `↑`/`↓`, без слов "По возрастанию/убыванию"
внутри самой кнопки.

Ряд с комбобоксом и кнопкой сортировки должен использовать `stretch`, чтобы
комбобокс забирал всё доступное место, а кнопка — только свой фиксированный
квадрат:
```python
row2 = QHBoxLayout()
row2.setSpacing(6)
row2.addWidget(self._filter_combo, 1)   # stretch=1 — забирает всё свободное место
row2.addWidget(self._sort_dir_btn, 0)   # stretch=0 — фиксированный квадрат
```

## Шаг 4 — увеличь минимальную ширину панели (страховка, не единственный фикс)

После шагов 1–3 сумма минимальных ширин будет маленькой, но всё равно проверь и
установи разумный запас, чтобы не было пограничных случаев:
```python
panel.setMinimumWidth(300)   # было 280 — увеличить с запасом
```
И в `ErrorEditorPage.__init__`, где создаётся `splitter.setSizes([320, 880])`,
подними первое число до **не меньше** значения из `panel.setMinimumWidth(...)`
плюс 20px запаса:
```python
splitter.setSizes([340, 860])
```

## Шаг 5 — обязательная проверка перед тем как считать задачу выполненной

Это не опционально. Агент должен **фактически проверить**, а не предположить:

1. Запусти приложение, открой "Редактор ошибок", загрузи любой GeoJSON.
2. Уменьши окно приложения до `1200×720` (минимальный размер, см.
   `MainWindow.setMinimumSize(1200, 720)` в `ui/main_window.py`) и убедись, что:
   - Кнопки "← Пред." / "След. →" видны полностью, панель списка **не наезжает**
     на детальную панель справа (никакого текста из правой панели не должно быть
     видно "торчащим" слева от границы сплиттера).
   - Кнопка "↑"/"↓" сортировки — компактный квадрат, полностью внутри своей строки,
     не вылезает за пределы левой панели.
3. Потяни сплиттер вручную (программно через `splitter.moveSplitter(280, 1)` в
   тестовом скрипте или логическую проверку) до минимально возможной ширины левой
   панели и убедись, что ничего не переполняется и не наезжает на соседнюю панель.
4. Если после всех шагов остаётся обрезание текста в самих кнопках "← Пред."/"След. →"
   при экстремально узкой панели — это допустимо (Qt может подрезать текст), но
   **не допускается** визуальное наезжание одной панели на другую и не допускается
   "оторванная" от общего ряда кнопка (как на скрине B).
