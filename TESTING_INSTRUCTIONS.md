# Инструкции по тестированию исправлений

## Автоматические тесты (юнит-тесты)

### Запуск всех тестов

```bash
# Windows
python tests\test_ocr_pipeline_regression.py
python tests\test_ocr_cache_and_city_name.py
python tests\test_sign_handler_finalize_remaining.py

# Linux/Mac
python tests/test_ocr_pipeline_regression.py
python tests/test_ocr_cache_and_city_name.py
python tests/test_sign_handler_finalize_remaining.py
```

### Ожидаемый результат

Каждый файл должен вывести:
```
✓ test_name_1
✓ test_name_2
...
✅ Все тесты пройдены!
```

Если тесты падают с ошибками импорта, убедитесь что:
1. Вы находитесь в корне проекта
2. Установлены зависимости: `pip install -r requirements.txt`

## Ручное тестирование (обязательно!)

Юнит-тесты проверяют только внутреннюю логику. **Критически важно** протестировать на реальном видео.

### Подготовка

1. Выберите тестовое видео с GPS-треком, содержащее:
   - Текстовые знаки (3.24 с подписью, ограничения скорости)
   - Указатели населённых пунктов (5.22.1, 5.23.3)
   - Длительность 2-5 минут (достаточно для проверки всех режимов)

2. Сделайте резервную копию текущих настроек (если нужно вернуться)

### Тест 1: Pipeline режим (БАГ A + B) — КРИТИЧЕСКИ ВАЖНО

**Цель:** Проверить что Pipeline не падает на текстовых знаках

1. Запустите приложение
2. `Settings → Processing Mode → Pipeline`
3. Загрузите тестовое видео + GPX
4. Нажмите "Start Processing"

**Ожидаемое поведение:**
- ✅ Обработка идёт до 100%, без остановок
- ✅ В логе НЕТ строк `AttributeError: ... has no attribute 'bbox'`
- ✅ Итоговый GeoJSON содержит знаки на всём видео
- ✅ У текстовых знаков (3.24 и т.д.) поле `SEM250` / `MVALUE` **заполнено** (не пустая строка)

**Если тест провален:**
- Pipeline останавливается через 5-10 секунд
- В логе есть `AttributeError`
- GeoJSON почти пустой или содержит только первые несколько знаков
- → Сообщите об ошибке, приложите лог

### Тест 2: Process Pool — производительность (БАГ C)

**Цель:** Проверить что Process Pool не медленнее single_thread

1. `Settings → Processing Mode → Single Thread`
2. Обработайте тестовое видео, **запишите время обработки и FPS из лога**
3. `Settings → Processing Mode → Process Pool`
4. Обработайте **то же самое видео**, запишите время и FPS

**Ожидаемое поведение:**
- ✅ Process Pool быстрее или сопоставим с Single Thread (± 20%)
- ✅ В логе видно `[SmartSkip] FPS: X.X` — значение не должно быть аномально низким
- ✅ Количество найденных знаков **сопоставимо** (± 5-10%) между режимами

**Если тест провален:**
- Process Pool в 2+ раза медленнее
- FPS значительно ниже
- → Возможно OCR-кэш не работает, нужна диагностика

### Тест 3: Указатели населённых пунктов (БАГ D)

**Цель:** Проверить что названия городов сохраняются

1. Обработайте видео со знаками типа 5.22.1, 5.22.2, 5.23.1, 5.23.2, 5.23.3
2. Откройте результирующий GeoJSON в текстовом редакторе
3. Найдите знаки с `"TYPE": "5.22.1"` или `"TYPE": "5.23.3"`

**Ожидаемое поведение:**
- ✅ Поле `"SEM250"` или `"MVALUE"` содержит название города (например, `"минск"`, `"гомель"`)
- ✅ Название **не пустое** и **соответствует** знаку на видео

**Если тест провален:**
- Поле пустое: `"SEM250": ""`
- → БАГ D не исправлен, проверьте версию кода

### Тест 4: Короткие видео (БАГ E)

**Цель:** Проверить что знаки в конце видео не теряются

1. Обработайте **короткое** видео (30-60 секунд), где знаки видны в последних кадрах
2. Проверьте лог обработки — должна быть строка:
   ```
   [SignHandler] Финализировано X активных знаков в конце видео
   ```
   (где X > 0, если действительно были активные знаки)

**Ожидаемое поведение:**
- ✅ Все знаки с >= 4 наблюдениями присутствуют в GeoJSON
- ✅ Знаки, видимые в последних 1-2 секундах видео, **сохранены**

**Если тест провален:**
- Последние 1-3 знака отсутствуют
- В логе нет строки о финализации
- → БАГ E не исправлен

### Тест 5: Сравнение режимов (общая проверка)

**Цель:** Убедиться что все режимы дают сопоставимые результаты

Обработайте **одно и то же видео** во всех трёх режимах:
1. Single Thread
2. Pipeline
3. Process Pool

**Сравните:**
- Количество найденных знаков
- Время обработки
- Наличие текста на знаках

**Ожидаемое поведение:**
- ✅ Количество знаков различается не более чем на 5-10%
- ✅ У всех режимов текстовые поля заполнены
- ✅ Pipeline и Process Pool работают (не крашатся)

**Если тест провален:**
- Pipeline находит в 10+ раз меньше знаков
- Process Pool значительно медленнее Single Thread
- → Требуется диагностика

## Диагностика проблем

### Pipeline падает с ошибкой

1. Проверьте лог на наличие `AttributeError` или `has no attribute 'bbox'`
2. Убедитесь что изменения в `processing/detector_thread.py` применены корректно
3. Проверьте что `core/frame.py` содержит `@property bbox`

### Process Pool медленный

1. Проверьте лог на наличие статистики кэша (если добавлена)
2. Убедитесь что `core/detector.py` содержит `self._ocr_cache`
3. Проверьте метод `_read_text()` — он должен использовать кэш

### Текст на знаках пустой

1. Проверьте что `_on_ocr_result()` и `_on_ocr_result_pool()` пишут в `tracked_sign.text_results`
2. Убедитесь что `_submit_ocr_task()` сохраняет `TrackedSign` в `_pending_ocr`, а не `DetectedSign`

### Названия городов пустые

1. Проверьте `core/sign.py` — метод `best_city_name()` должен использовать `most_common()`
2. Проверьте `processing/ocr_pool.py` — `_ocr_city()` должен возвращать строку, не JSON

### Знаки в конце видео теряются

1. Проверьте `core/sign_handler.py` — должен быть метод `finalize_remaining()`
2. Проверьте `processing/detector_thread.py` — в блоке `finally` должен быть вызов `finalize_remaining()`
3. Проверьте лог — должна быть строка о финализации
