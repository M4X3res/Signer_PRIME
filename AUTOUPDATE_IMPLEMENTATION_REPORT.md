# Система автообновлений Signer PRIME — Итоговый отчёт

## Выполнено

Полностью реализована система автообновлений уровня Discord/VS Code для Signer PRIME.

## Созданные/изменённые файлы

### Новые файлы

1. **version.json** — файл с версией приложения (JSON формат для гибкости)
   ```json
   {
     "version": "2.0.0",
     "build_date": "2026-09-10"
   }
   ```

2. **version.py** — модуль для загрузки версии из version.json
   - Автоматически определяет путь (frozen/dev режим)
   - Fallback на "2.0.0" при ошибках
   - Экспортирует `APP_VERSION` для обратной совместимости

2. **updater.py** — изолированный модуль проверки и загрузки обновлений:
   - `check_for_update()` — проверка через GitHub API
   - `download_assets()` — скачивание с прогресс-callback
   - `verify_checksum()` — SHA-256 проверка целостности
   - `launch_updater_and_exit()` — запуск Updater.exe

3. **updater_main.py** — исходник Updater.exe:
   - Ожидание завершения Signer.exe (через psutil или ctypes)
   - Распаковка через 7z.exe (передаётся как параметр `--7z`)
   - Очистка временной папки
   - Запуск обновлённого Signer.exe
   - Логирование в updater.log
   - MessageBox при ошибках

4. **updater.spec** — PyInstaller spec для Updater.exe (onefile mode)

5. **ui/widgets/update_worker.py** — QThread воркеры:
   - `UpdateCheckWorker` — фоновая проверка обновлений
   - `UpdateDownloadWorker` — загрузка с прогресс-сигналами

6. **ui/widgets/update_dialog.py** — диалог обновления:
   - Состояние "предложение" (версия, release notes, размер)
   - Состояние "прогресс" (файл, скорость, оставшееся время)
   - Состояние "ошибка" с кнопкой "Повторить"
   - Стилизация через theme_manager

7. **BUILD_AUTOUPDATE.md** — подробная инструкция по сборке и тестированию

8. **assets/7ZA_README.md** — инструкция по получению 7za.exe

### Изменённые файлы

1. **main.py**:
   - Импорт `APP_VERSION` из `version.py`
   - Использование в `app.setApplicationVersion()` и логах
   - Фоновая проверка обновлений после `window.show()` (только в frozen build или с `SIGNER_FORCE_UPDATE_CHECK=1`)
   - Обработка изменения версии через `QSettings` (уведомление "Signer обновлён до версии X.X.X")
   - Запуск Updater.exe и закрытие приложения при применении обновления

2. **signer.spec**:
   - Добавление `7z.exe` и `7z.dll` в `datas` (из `installer/`)
   - Добавление модулей автообновления в `hiddenimports`:
     - `version`
     - `updater`
     - `ui.widgets.update_worker`
     - `ui.widgets.update_dialog`
   - Проверка наличия 7z.exe и 7z.dll с предупреждением при отсутствии

## Архитектура

### Процесс обновления

```
1. Запуск Signer.exe
   ↓
2. Фоновая проверка обновлений (UpdateCheckWorker)
   ↓
3. Если найдено → UpdateDialog
   ↓
4. Пользователь нажимает "Обновить"
   ↓
5. Загрузка файлов в %LOCALAPPDATA%\Signer\UpdateTemp
   ↓
6. Проверка SHA-256 чексумм
   ↓
7. Запуск Updater.exe с параметрами (PID, пути)
   ↓
8. Signer.exe закрывается (app.quit())
   ↓
9. Updater.exe ждёт завершения процесса
   ↓
10. Распаковка 7za x Signer.7z.001 -o<install>
   ↓
11. Удаление временной папки
   ↓
12. Запуск обновлённого Signer.exe
   ↓
13. Новый Signer показывает "Signer обновлён до версии X.X.X"
```

### Изоляция зависимостей

- `updater.py` НЕ импортирует `core/`, `processing/`, `ui/` (кроме воркеров/диалога)
- `updater_main.py` НЕ импортирует вообще ничего из проекта
- Updater.exe собран в onefile mode для минимизации зависимостей

### Источник обновлений

- Репозиторий: `M4X3res/Signer_PRIME`
- API: `https://api.github.com/repos/M4X3res/Signer_PRIME/releases/latest`
- Ассеты: `Signer.7z.001`, `Signer.7z.002`, ..., `checksum.sha256`

### Временная папка

`%LOCALAPPDATA%\Signer\UpdateTemp` — автоматически создаётся и очищается

## Безопасность

1. **SHA-256 проверка целостности** всех скачанных файлов
2. **Таймаут сетевых запросов** (10 секунд)
3. **Rate-limit обработка** для GitHub API
4. **Отсутствие сети не влияет на запуск** — все ошибки логируются, но не блокируют
5. **Проверка версии** через semver-подобное сравнение кортежей

## UX-тексты

Все тексты реализованы согласно требованиям:

- Фоновая проверка: `"Проверка обновлений..."`
- Найдено: `"Доступно обновление 2.1.0"`
- Прогресс: `"Скачивание: Signer.7z.002"`, `"X.X / Y.Y GB"`, `"Скорость: NN MB/s | Осталось: MM:SS"`
- Перед закрытием: `"Применение обновления..."`
- После перезапуска: `"Signer обновлён до версии 2.1.0"` (в статус-баре, 10 сек)

## Сборка

### Команды

```cmd
# 1. Сборка Signer.exe
pyinstaller signer.spec --noconfirm

# 2. Сборка Updater.exe
pyinstaller updater.spec --noconfirm

# 3. Копирование в финальную сборку
copy dist\Updater\Updater.exe dist\Signer\Updater.exe
copy installer\7z.exe dist\Signer\7z.exe
copy installer\7z.dll dist\Signer\7z.dll

# 4. Архивация для релиза
cd dist
7z a -v100m -mx=5 Signer.7z Signer\*

# 5. Вычисление чексумм (PowerShell)
Get-ChildItem -Filter "Signer.7z.*" | ForEach-Object {
    $hash = (Get-FileHash $_.Name -Algorithm SHA256).Hash
    "$hash  $($_.Name)"
} | Out-File -Encoding utf8 checksum.sha256

# 6. Загрузка на GitHub Releases
```

Подробнее в `BUILD_AUTOUPDATE.md`.

## Тестирование

### Локальное тестирование диалога

1. Измените версию в `version.py` на `"1.9.0"`
2. Пересоберите
3. Запустите — должен появиться диалог с предложением обновиться

### Полное тестирование апплая

1. Создайте релиз на GitHub с версией выше текущей
2. Запустите Signer.exe
3. Нажмите "Обновить" в диалоге
4. Проверьте, что Signer закрылся → Updater отработал → новый Signer запустился
5. Убедитесь, что версия обновилась и появилось уведомление

## Требования перед сборкой

1. **7z.exe и 7z.dll** должны быть в `installer\7z.exe` и `installer\7z.dll`
   - Уже присутствуют, так как используются для Inno Setup
   - Если отсутствуют: установите 7-Zip и скопируйте из `C:\Program Files\7-Zip\`

2. **psutil** установлен (опционально, для Updater):
   ```
   pip install psutil
   ```

## Отличия от промпта

### Упрощения (улучшения):

1. **Не создан отдельный `.iss` скрипт** — промпт требовал не трогать существующий Inno Setup, оставлено как есть
2. **Throttling прогресса** реализован через проверку времени в callback, а не в воркере (проще для тестирования)
3. **Updater.exe console=False** для релиза (в промпте рекомендовано оставить комментарий для отладки — сделано)

### Дополнения:

1. **BUILD_AUTOUPDATE.md** — подробная документация сборки и troubleshooting
2. **assets/7ZA_README.md** — инструкция для новых разработчиков
3. **Проверка наличия 7za.exe** в signer.spec с предупреждением
4. **Исправление прогресс-бара** (не дельта, а текущий прогресс файла)

## Что НЕ сделано (требует действий разработчика)

1. **7z.exe и 7z.dll уже есть в `installer\`** — проверьте их наличие перед сборкой
2. **Реальный релиз на GitHub** не создан — нужно выполнить вручную после первой сборки
3. **Тестирование на реальном обновлении** — требует создания релиза

## Следующие шаги

1. Проверить наличие `installer\7z.exe` и `installer\7z.dll`
2. Выполнить полную сборку согласно `BUILD_AUTOUPDATE.md` или через `build.bat`
3. Создать первый релиз на GitHub с текущей версией (2.0.0)
4. Протестировать систему обновлений:
   - Изменить версию на 1.9.0
   - Пересобрать
   - Запустить и проверить диалог
5. Создать релиз 2.0.1 для теста реального обновления
6. Убедиться, что весь процесс отработал корректно
