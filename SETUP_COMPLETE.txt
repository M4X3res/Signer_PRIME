📦 СОЗДАННЫЕ СКРИПТЫ:

1️⃣  build_test.bat
   └─ Быстрая тестовая сборка (без архивации)
   └─ Для локального тестирования
   └─ Запускает приложение автоматически

2️⃣  build_release.bat
   └─ Полная сборка релиза
   └─ Создает многотомный архив (100MB части)
   └─ Вычисляет SHA-256 чексуммы
   └─ Подготавливает все файлы в папке release\

3️⃣  upload_release.ps1
   └─ Автоматическая загрузка на GitHub
   └─ Создает GitHub Release
   └─ Загружает все файлы из release\
   └─ Требует GitHub CLI (gh)

📚 ДОКУМЕНТАЦИЯ:

1️⃣  QUICK_RELEASE_GUIDE.md
   └─ Краткое руководство по сборке и публикации
   └─ Пошаговые инструкции
   └─ Чеклист перед релизом

2️⃣  SCRIPTS_README.md
   └─ Полная документация по всем скриптам
   └─ Настройка окружения
   └─ Устранение проблем
   └─ Примеры использования

   build_test.bat

┌─────────────────────────────────────────────────────────────────────────────┐
│  ПУБЛИКАЦИЯ РЕЛИЗА                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

1. Обновите версию в version.json
2. Обновите release_notes.txt
3. Запустите полную сборку:
   
   build_release.bat
   
4. Загрузите на GitHub:
   
   powershell -ExecutionPolicy Bypass -File upload_release.ps1
   
   Или загрузите файлы из release\ вручную

📋 ТРЕБОВАНИЯ:

✅ Python + PyInstaller:
   pip install pyinstaller

✅ 7-Zip (для build_release.bat):
   - Скопируйте 7z.exe и 7z.dll в installer\
   - Или скачайте: https://www.7-zip.org/

✅ GitHub CLI (для upload_release.ps1):
   winget install --id GitHub.cli
   gh auth login

📁 СТРУКТУРА ПОСЛЕ СБОРКИ:

build_test.bat создает:
  dist\Signer\
  └── Signer.exe (готово к запуску)

build_release.bat создает:
  release\
  ├── Signer.7z.001, .002, .003, ...   (архив по частям)
  ├── checksum.sha256                   (чексуммы)
  ├── release_notes.txt                 (описание релиза)
  └── README.md, BUILD_AUTOUPDATE.md    (документация)

💡 СОВЕТЫ:

• Перед каждым релизом запускайте build_test.bat для проверки
• Используйте семантическое версионирование (2.0.0, 2.1.0, 2.1.1)
• Пишите понятные release notes для пользователей
• Тестируйте автообновление со старой версии на новую
• Сохраняйте предыдущие релизы на случай отката
