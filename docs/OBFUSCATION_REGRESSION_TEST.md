# Regression Test Checklist для Обфусцированной Сборки

## Контекст
После исправлений в PROMPT_HARDEN_LICENSING требуется обязательный regression-тест 
обфусцированной сборки для подтверждения, что:
- Обфускация PyArmor работает корректно
- Система лицензирования функционирует в обфусцированном виде
- Основной функционал приложения не нарушен

## Предварительные требования

- [ ] Python с установленными зависимостями (`pip install -r requirements.txt`)
- [ ] PyInstaller установлен (`pip install pyinstaller`)
- [ ] PyArmor >= 9.0.0 установлен (`pip install pyarmor>=9.0.0`)
- [ ] Локальный dev-сервер лицензий (`signer-license-server`) настроен и запущен
- [ ] `SIGNER_LICENSE_SERVER_URL=http://localhost:8000` установлена в переменных окружения
- [ ] Тестовый лицензионный ключ создан в dev-сервере

## Шаг 1: Обфускация

```cmd
python scripts\build\obfuscate_licensing.py
```

**Проверки:**
- [ ] Скрипт завершился без ошибок
- [ ] Папка `build\obfuscated` создана
- [ ] Внутри `build\obfuscated\licensing` есть подпапка `pyarmor_runtime_*`
- [ ] Файлы `main.py`, модули `licensing\*.py` присутствуют в обфусцированной форме

**Проверка стабильности имени runtime (ШАГ 2):**
- [ ] Запустите обфускацию повторно 2-3 раза
- [ ] Убедитесь, что имя папки `pyarmor_runtime_*` стабильно (или runtime внутри `licensing/` благодаря `-i`)
- [ ] Если runtime внутри пакета: `build\obfuscated\licensing\pyarmor_runtime_000000\` существует

## Шаг 2: Сборка PyInstaller

```cmd
cd build\obfuscated
pyinstaller signer.spec --noconfirm
cd ..\..
```

**Проверки:**
- [ ] Сборка завершилась без ошибок
- [ ] `build\obfuscated\dist\Signer\Signer.exe` создан
- [ ] `build\obfuscated\dist\Signer\_internal\` содержит зависимости
- [ ] PyArmor runtime присутствует в одном из мест:
  - `build\obfuscated\dist\Signer\_internal\pyarmor_runtime_*\` ИЛИ
  - `build\obfuscated\dist\Signer\_internal\licensing\pyarmor_runtime_000000\`


- [ ] Сервер запущен на http://localhost:8000
- [ ] Админ-панель доступна: http://localhost:8000/admin

**Создание тестового ключа (если нужно):**
1. Войти в админ-панель (логин/пароль из docker-compose.dev.yml)
2. Создать новую лицензию с планом "monthly" или "yearly"

## Шаг 7: Тест Grace Period (имитация)

```cmd
# Остановить dev-сервер
cd signer-license-server
docker-compose -f docker-compose.dev.yml down

# Перезапустить приложение
cd build\obfuscated\dist\Signer
Signer.exe
```

**Проверки:**
- [ ] Приложение запускается без прямого краша
- [ ] При попытке refresh токена (runtime monitor) логируется CONNECTION_ERROR
- [ ] В течение grace period (3 дня по текущим настройкам) приложение продолжает работать
- [ ] Статус лицензии: GRACE_PERIOD (можно проверить в логах)

**Восстановить сервер:**
```cmd

docker-compose -f docker-compose.dev.yml up -d
```

## Шаг 12: Проверка runtime-мониторинга лицензии (ШАГ 1)

**Цель:** Убедиться, что при истечении лицензии во время обработки данные не теряются.

**Сложный сценарий (требует модификации кода для теста):**

Временно измените в обфусцированном коде (ДО сборки) константу в `licensing/license_manager.py`:
```python
RUNTIME_CHECK_INTERVAL_HOURS = 0.1  # 6 минут вместо 6 часов
```

Пересоберите, затем:

1. Запустите приложение
2. Начните обработку ДЛИННОГО видео (5-10 минут)
3. Пока обработка идёт, вручную удалите токен:
   ```cmd
   del %LOCALAPPDATA%\Signer\license.token
   ```
4. Ждите, пока runtime monitor обнаружит отсутствие лицензии (~6 минут)

**Проверки:**
- [ ] Обработка НЕ останавливается резко
- [ ] Приложение завершает текущее сохранение GeoJSON
- [ ] ПОСЛЕ завершения сохранения показывается диалог "Лицензия недействительна"
- [ ] Приложение закрывается
- [ ] Файл GeoJSON сохранён корректно (не повреждён)

**Упрощённый сценарий (если длинное видео недоступно):**
- Просто проверить, что при ручном вызове `_on_license_status_changed(LicenseStatus.EXPIRED)` 
  во время обработки приложение корректно ждёт сигнала `results_saved` (см. изменения в `main.py`)

## Если тесты не проходят

### Краш при запуске с NameError
→ Вернитесь к ШАГ 0, убедитесь, что исправление `REQUESTS_AVAILABLE` применено

### Ошибка импорта PyArmor runtime
→ Проверьте, что runtime-папка присутствует в `_internal/`
→ Убедитесь, что `-i` флаг используется в `obfuscate_licensing.py` для пакетов

### Лицензия не активируется
→ Проверьте dev-сервер: `curl http://localhost:8000/health`
→ Проверьте переменную окружения `SIGNER_LICENSE_SERVER_URL`
→ Проверьте логи `roadscan.log`

### Декомпиляция успешна
→ Убедитесь, что сборка идёт из `build\obfuscated`, а не из корня
→ Проверьте версию PyArmor: `pyarmor --version`
