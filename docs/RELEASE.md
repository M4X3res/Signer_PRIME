# Релиз

## Совместимость 2.0.5 с установленными 2.0.3 и 2.0.4

Сохраните `release_baselines/2.0.3` и `release_baselines/2.0.4` (или их полные инвентари в `release_inventories`). Сборка включает списки файлов обеих версий в `manifest.json`, но не публикует для них `delta-from-*.json/zip`: старый клиент передаёт неправильное имя манифеста дельты. Без дельта-ассетов он сам выбирает полный архив `Signer.7z.*` и обновляет существующую установку через обычную кнопку обновления. Загрузка будет больше; отдельная ручная установка не требуется.

Проверка релиза запрещает публикацию дельт для 2.0.0–2.0.4 и требует инвентари 2.0.3/2.0.4 для выпуска 2.0.5. Для клиентов начиная с 2.0.5 генерация дельт сохраняется. Не добавляйте старые дельта-пакеты вручную в GitHub Release.

1. Обновите `version.json`.
   Подготовьте `docs/release_notes.txt`: этот файл обязателен для `scripts/build/finish_release.py` и копируется в релиз. Не переносите его в архив вместе с историческими отчётами.
2. Запустите `scripts/build/prepare_release.bat` из корня проекта.
3. Выполните preflight и проверку артефактов.
4. Проверьте установку на чистом каталоге и обновление поверх предыдущего выпуска.
5. Опубликуйте подготовленные файлы через `upload_release.bat` или `upload_release.ps1`.

В релиз должны попасть исполняемые файлы, ресурсы UI, модели, изображения знаков, updater и манифест. Секреты, токены лицензии, `.signer_clip_cache`, `.venv`, `test_data` и содержимое `docs/archive` в рабочую сборку не включаются.

Текущая версия проекта хранится в `version.json`; документы в архиве могут ссылаться на старые версии и старые пути.
