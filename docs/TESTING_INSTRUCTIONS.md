## ЧАСТЬ 1 — Process Pool Performance

### 1. Запустить с профилированием
```bash
# В настройках выбрать Process Pool
# Запустить обработку видео 1920×1080
# Наблюдать логи с префиксом PERF-ANALYSIS-1
```

### 2. Искомые метрики в логах
```
[PERF-ANALYSIS-1] Worker received image_bytes: X.XX MB
[PERF-ANALYSIS-1] Worker detect() took: X.XXX sec
[PERF-ANALYSIS-1] ResultAggregator future.result() took: X.XXX sec  ← ДОЛЖНО УПАСТЬ
```

### 3. Ожидаемый результат
- **ДО фикса:** `future.result()` занимало ~50-100 мс на десериализацию 6 МБ
- **ПОСЛЕ фикса:** `future.result()` должно упасть до <10 мс (только detections, без image_bytes)
- **Общий FPS:** должен вырасти на 10-20% на тяжёлых видео

### 4. Проверить память
```bash

# Убедиться что память не растёт бесконечно (должна быть стабильна после первых 100 кадров)
```

## ЧАСТЬ 2 — Video Player HTTP Range

### 1. Подготовить тестовое видео
```bash
# Создать большое видео БЕЗ +faststart (метаданные в конце)
ffmpeg -i input.mp4 -c copy -movflags -faststart test_video.mp4
# Должно быть > 1 ГБ для явного проявления проблемы
```

### 2. Запустить сервер и открыть карту
```bash
# Убедиться что test_video.mp4 в списке VIDEOS в config
# Открыть http://127.0.0.1:3000/map
# Кликнуть на маркер знака с видео
```

### 3. Проверить DevTools
- **Network:** найти запрос `/api/video/<idx>`
- **Статус:** должен быть `206 Partial Content`
- **Headers Response:**
  - `Content-Range: bytes X-Y/Z` (ОДИН заголовок, не два!)
  - `Content-Length: N` (ОДИН заголовок)
- **Видео:** должно загрузиться и показать длительность БЕЗ timeout

### 4. Тест suffix-range (curl)
```bash
# Запросить последние 1024 байта
curl -v -H "Range: bytes=-1024" http://127.0.0.1:3000/api/video/0 -o last_1024.bin

# Сравнить с реальным концом файла
tail -c 1024 "path/to/video.mp4" > expected_1024.bin
fc /b last_1024.bin expected_1024.bin

# Вывод должен быть: "FC: различий не найдено"
```

### 5. Тест перемотки
```javascript
// В консоли браузера на /map
video.currentTime = 120;  // Перемотать на 2 минуты
// Видео должно переместиться БЕЗ зависания
```

## ЧАСТЬ 3 — Map Tiles Configuration

### 1. Открыть настройки
- Запустить приложение
- Настройки → секция "Карта"

### 2. Тест: Google Hybrid
```
URL тайлов: https://mt1.google.com/vt/lyrs=y&x={x}&y={y}&z={z}
Атрибуция: © Google
Макс. зум: 20
```
- Нажать "Применить"
- Перейти на вкладку "Карта"
- Должна загрузиться спутниковая подложка Google

### 3. Тест: OpenTopoMap
```
URL тайлов: https://{s}.tile.opentopomap.org/{z}/{x}/{y}.png
Атрибуция: © OpenTopoMap
Макс. зум: 17
```
- Применить → Карта
- Должна загрузиться топографическая подложка

### 4. Тест: Fallback на OSM
```bash
# Остановить сервер
# Открыть карту (должна работать с кэшированным HTML)
# Карта должна загрузиться с дефолтной OSM подложкой (fallback)
```

### 5. Проверить сохранение
- Изменить URL тайлов на произвольный
- Применить → Закрыть приложение
- Запустить снова → Настройки → Карта
- URL должен остаться изменённым (сохранён в QSettings)

## Регрессионные тесты

### Проверить что НЕ сломалось
1. **Single Thread** режим — должен работать как раньше
2. **Pipeline** режим — должен работать как раньше
3. **Карта без видео** — маркеры без видео должны открываться
4. **Видео < 100 МБ** — должны грузиться без Range-запросов (полный файл)
5. **Старые настройки** — если map_tile_url отсутствует в QSettings, должен применяться дефолт OSM
