## Архитектура потоков данных

```
MainWindow
    ↓ start_requested
ProcessingController
    ↓ creates
VideoReaderThread → DetectorThread
    ↓ emit_position (каждую секунду)
MapServer (Flask/SocketIO)
    ↓ socket.emit('position')
Map HTML (JavaScript)
    ↓ updatePositionMarker()
Leaflet Map ← обновление маркера
```

## Сигналы и события

### PyQt Signals
- `frame_ready(QPixmap)` - новый кадр для UI
- `progress(int, int)` - прогресс обработки
- `stats(int, int, float)` - статистика (кадры, знаки, fps)
- `sign_found(str, str, float)` - детектирован знак
- `finished()` - обработка завершена
- `error(str)` - ошибка обработки
- `jump_to_second(int)` - запрос перехода к секунде

### Socket.IO Events
- `connect` / `disconnect` - состояние соединения
- `processing_state` - статус обработки (active: bool)
- `data_ready` - данные готовы (ready: bool)
- `position` - текущая позиция в видео (seconds: int)
- `new_sign` - новый знак детектирован (sign: dict)
- `sign_updated` - знак изменен (id: string)
- `sign_deleted` - знак удален (id: string)
- `processing_finished` - обработка завершена (finished: bool)

## API Endpoints

### GET
- `/` - главная страница карты (HTML)
- `/api/track` - GPS трек (массив [lat, lon])
- `/api/signs` - все знаки (массив объектов)
- `/api/sign/<id>` - детали знака (GeoJSON feature)
- `/api/sign_types` - типы знаков (массив {type, name})
- `/api/img/<id>` - иконка знака (PNG)
- `/api/geojson_export` - экспорт GeoJSON (download)
- `/api/jump?seconds=X` - переход к секунде
- `/api/gps_at_time?seconds=X` - GPS координаты по времени ✨ NEW

### PATCH
- `/api/sign/<id>` - обновление знака (body: {type, description})

### DELETE
- `/api/sign/<id>` - удаление знака

## Использование

### Запуск обработки
1. Пользователь нажимает "Начать обработку" в Dashboard
2. Создается ProcessingController (ленивая загрузка)
3. Запускается Flask сервер карты
4. Начинается обработка видео
5. Позиция обновляется каждую секунду
6. Детектированные знаки добавляются в реальном времени

### Live режим
1. Пользователь включает кнопку "Live" на карте
2. Карта начинает следить за текущей позицией
3. Маркер позиции отображается и центрируется
4. Toast уведомления о новых знаках

### После завершения
1. Пользователь нажимает "Завершить"
2. Обработка завершается мягко (дожидается текущего видео)
3. GeoJSON сохраняется через FinalHandler
4. Карта автоматически перезагружается с новыми данными
5. Все кнопки (Live, Jump, фильтры) работают
6. Можно редактировать знаки, переходить к кадрам

### Пауза/Возобновление
1. Пользователь нажимает "Пауза"
2. VideoReaderThread приостанавливается
3. Кнопка меняется на "Продолжить"
4. При нажатии - обработка возобновляется
5. Карта остается функциональной

## Обработка ошибок - примеры

### Нет GPX файла
```javascript
// Frontend
toast("Ошибка загрузки трека", "err")
console.error("Error loading track:", err)

// Backend
return jsonify({"error": "no gpx file"}), 404
```

### Нет GeoJSON
```python
# Backend проверяет существование
if not os.path.exists(config.PATH_TO_GEOJSON):
    return jsonify([])  # пустой массив вместо ошибки
```

### Socket disconnect
```javascript
socket.on("disconnect", () => {
  console.log("Socket disconnected");
  toast("Отключено от сервера", "warn");
});
// Автоматический reconnect через reconnection: true
```

### API ошибка
```javascript
const r = await fetch(url);
if (!r.ok) throw new Error(`HTTP ${r.status}`);
const data = await r.json();
if (data.error) throw new Error(data.error);
```
