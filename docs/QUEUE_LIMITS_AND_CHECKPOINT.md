# Ограничение очередей и автосохранение checkpoint

## Обзор

Две критические оптимизации для **стабильности и надёжности**:

1. **Ограничение размера очередей** — предотвращает утечку памяти
2. **Автосохранение checkpoint** — восстановление после краша

## 1. Ограничение очередей

### Проблема

В оригинальной реализации:
```python
frame_queue = queue.Queue(maxsize=8)    # ✅ ограничена
result_queue = queue.Queue()            # ❌ неограничена!
```

Если `FinalHandler` не успевает забирать знаки из `result_queue`, очередь растёт бесконечно → **утечка памяти**.

### Решение

```python
FRAME_QUEUE_SIZE = 100   # кадров (увеличено для стабильности)
RESULT_QUEUE_SIZE = 500  # знаков (новое!)

frame_queue = queue.Queue(maxsize=100)
result_queue = queue.Queue(maxsize=500)
```

### Механизм backpressure

Когда `result_queue` переполняется:

```python
try:
    result_queue.put(sign, timeout=1.0)
except queue.Full:
    # Ждём освобождения места (блокируем)
    result_queue.put(sign, block=True)
```

**Эффект:** DetectorThread автоматически замедляется если обработка результатов отстаёт.

### Потребление памяти

| Очередь | Размер | Память |
|---------|--------|--------|
| `frame_queue` | 100 кадров | ~200 МБ (1920x1080 RGB) |
| `result_queue` | 500 знаков | ~5 МБ (TrackedSign объекты) |
| **Итого** | | **~205 МБ** (стабильно) |

**До оптимизации:** неограниченный рост до нескольких ГБ!

## 2. Автосохранение checkpoint

### Проблема

При краше приложения:
- ❌ Теряется весь прогресс обработки
- ❌ Нужно начинать с начала (часы работы)
- ❌ Нет защиты от сбоев питания, BSOD и т.д.

### Решение

Автоматическое сохранение состояния каждые **60 секунд**:

```python
checkpoint_data = {
    'version': '1.0',
    'timestamp': time.time(),
    'config': {
        'INDEX_OF_FRAME': 15430,
        'INDEX_OF_VIDEO': 2,
        'INDEX_OF_All_FRAME': 142830,
        'VIDEOS': [...],
        ...
    },
    'signs': {
        'result_signs': [...],  # финализированные знаки
        'active_signs': [...],  # в процессе трекинга
        'turns': [...],         # данные о поворотах
    },
    'stats': {
        'frames_processed': 8456,
        'signs_found': 127,
    }
}
```

### Атомарное сохранение

```python
# 1. Сохраняем во временный файл
joblib.dump(data, "checkpoint.pkl.tmp", compress=3)

# 2. Атомарная замена (предотвращает повреждение)
os.remove("checkpoint.pkl")
os.rename("checkpoint.pkl.tmp", "checkpoint.pkl")
```

### Восстановление

При следующем запуске:

1. **Проверка наличия** checkpoint
2. **Диалог пользователю**: продолжить или начать заново?
3. **Восстановление состояния**: config + знаки + позиция в видео
4. **Продолжение обработки** с места остановки

### UI Integration

**При старте обработки:**
```
┌─────────────────────────────────────────┐
│  Восстановление прогресса               │
├─────────────────────────────────────────┤
│  Найден сохранённый прогресс обработки. │
│                                         │
│  Хотите продолжить с места остановки?   │
│                                         │
│         [Да]          [Нет]             │
└─────────────────────────────────────────┘
```

**Да** → загружает checkpoint и продолжает  
**Нет** → удаляет checkpoint и начинает заново

### Автоматическая очистка

Checkpoint удаляется автоматически:
- ✅ После успешного завершения обработки
- ✅ После сохранения финального GeoJSON
- ✅ Если пользователь выбрал "Нет" в диалоге

### Размер checkpoint файла

```python
Типичный размер: 500 КБ - 5 МБ (зависит от количества знаков)
Сжатие: joblib.dump(..., compress=3)  # zlib compression
```

## Как это работает

### Цикл автосохранения

```
DetectorThread обрабатывает кадр
    ↓
Финализирует знак → добавляет в result_queue
    ↓
Вызывает controller.save_checkpoint()
    ↓
Проверяет throttling (прошло ≥60 сек?)
    ↓
    Да → Сохраняет checkpoint.pkl
    Нет → Пропускает
```

### Throttling

```python
last_save = 0

def save_checkpoint():
    now = time.time()
    if now - last_save < 60:
        return  # слишком рано
    
    last_save = now
    # ... сохранение
```

**Почему 60 секунд?**
- Меньше → частые записи на диск (износ SSD, падение производительности)
- Больше → больше потерь при краше
- 60 сек → оптимальный баланс

## Производительность

### Overhead автосохранения

| Операция | Время | Частота |
|----------|-------|---------|
| Сохранение checkpoint | 50-200 мс | Раз в 60 сек |
| Загрузка checkpoint | 100-300 мс | При старте |

**Влияние на FPS:** < 1% (незначительно)

### Overhead ограничения очередей

| Операция | Было | Стало |
|----------|------|-------|
| `queue.put()` | O(1) | O(1) + блокировка при переполнении |
| Потребление памяти | Неограниченное | 205 МБ (фиксированное) |

**Backpressure срабатывает только** если:
- FinalHandler слишком медленный (маловероятно)
- Очередь результатов забита (защита от краша)

## Настройки

### В коде (`processing/processing_controller.py`)

```python
class ProcessingController:
    FRAME_QUEUE_SIZE = 100      # кадров
    RESULT_QUEUE_SIZE = 500     # знаков
    CHECKPOINT_INTERVAL = 60    # секунд
    CHECKPOINT_PATH = "checkpoint.pkl"
```

### Рекомендации

**Для машин с большой RAM (16GB+):**
```python
FRAME_QUEUE_SIZE = 200
RESULT_QUEUE_SIZE = 1000
```

**Для машин с малой RAM (8GB):**
```python
FRAME_QUEUE_SIZE = 50
RESULT_QUEUE_SIZE = 250
```

**Для частого автосохранения:**
```python
CHECKPOINT_INTERVAL = 30  # каждые 30 сек
```

**Для редкого автосохранения:**
```python
CHECKPOINT_INTERVAL = 120  # каждые 2 минуты
```

## API

### ProcessingController

```python
controller = ProcessingController()

# Проверка наличия checkpoint
if controller.has_checkpoint():
    # Загрузить и продолжить
    controller.load_checkpoint()
    controller.start()

# Ручное сохранение
controller.save_checkpoint()

# Удаление checkpoint
controller.delete_checkpoint()
```

### DetectorThread

```python
# Автоматически вызывает checkpoint
detector = DetectorThread(
    frame_queue, 
    result_queue,
    controller=controller  # передаём для checkpoint
)
```

## FAQ

**Q: Сколько места занимает checkpoint?**  
A: 500 КБ - 5 МБ в зависимости от количества знаков.

**Q: Можно ли отключить автосохранение?**  
A: Да, установите `CHECKPOINT_INTERVAL = 0` (не рекомендуется).

**Q: Что если checkpoint старый (несколько дней)?**  
A: Система загружает любой checkpoint. Проверьте путь к видео перед запуском.

**Q: Безопасно ли продолжать с checkpoint если изменились видео?**  
A: Нет! Удалите checkpoint и начните заново если видео изменились.

**Q: Влияет ли на производительность?**  
A: Минимально (< 1%). Сохранение 50-200 мс раз в 60 сек.

**Q: Работает ли с массовой обработкой нескольких папок?**  
A: Да, checkpoint сохраняет текущее видео и позицию.
