# Инструкция по тестированию исправления Process Pool

**Цель**: Проверить что краш 0xC0000409 исправлен агрессивным shutdown

---

## Что исправлено

1. **Env vars в worker процессах** — OpenMP/MKL правильно настроены
2. **Агрессивный shutdown** — worker процессы принудительно убиваются (terminate/kill)
3. **Graceful error handling** — aggregator не крашится при TimeoutError
4. **Проверки executor** — нет AttributeError при submit в None

---

## Известные ограничения

⚠️ **Preview не отображается** в Process Pool режиме

**Почему**: Qt signals не поддерживают cross-process передачу numpy arrays (ProcessedFrame.image).

**Это нормально**: 
- Счётчик кадров работает
- Статистика обновляется
- GeoJSON сохраняется корректно

---

## Порядок тестирования

### 1. Подготовка

```bash
# Запустите приложение
python main.py
```

### 2. Настройки

1. Откройте Settings (шестерёнка справа)
2. Найдите "Режим обработки"
3. Выберите **"Process Pool"**
4. **Workers**: оставьте "0 (авто)" или установите 2-4
5. Нажмите "Сохранить"

### 3. Загрузка данных

1. Загрузите тестовое видео (короткое, 2-5 минут)
2. Загрузите соответствующий GPX
3. Нажмите "Начать обработку"

### 4. Наблюдение

**Ожидается**:
- ✅ Счётчик кадров растёт (внизу экрана)
- ✅ Статистика обновляется (FPS, знаки)
- ❌ **Preview НЕ показывается** (чёрный экран) — это нормально!
- ✅ В консоли/логе: "[DetectorProcessPool] started with N workers"

**Не ожидается**:
- ❌ Приложение зависает
- ❌ Счётчик кадров застывает
- ❌ Ошибки в консоли

### 5. Завершение (КРИТИЧНО)

**Через 50-100 кадров**:
1. Нажмите **"Завершить"**
2. Подождите 2-3 секунды

**Ожидается**:
- ✅ Приложение НЕ крашится (exit code -1073740791)
- ✅ В консоли: "[DetectorProcessPool] Принудительное завершение worker процессов..."
- ✅ В консоли: "[DetectorProcessPool] Worker процессы завершены"
- ✅ Появляется диалог сохранения GeoJSON
- ✅ GeoJSON создаётся и **не пустой**

**Не ожидается**:
- ❌ `Process finished with exit code -1073740791 (0xC0000409)`
- ❌ Приложение зависает навсегда
- ❌ Python.exe процессы остаются в Task Manager

### 6. Проверка результата

1. Откройте сохранённый GeoJSON
2. **Проверьте**:
   - Файл не пустой (размер > 1KB)
   - Содержит `"features": [...]`
   - Есть несколько знаков (хотя бы 1-2)

### 7. Проверка Task Manager (опционально)

**После завершения**:
1. Откройте Task Manager
2. Проверьте: нет ли висячих `python.exe` процессов
3. **Ожидается**: только 1 процесс (главное приложение)

## Логи для диагностики

Если краш всё равно происходит, **соберите**:

### 1. roadscan.log
Последние 50-100 строк перед крашем:
```bash
tail -n 100 roadscan.log
```

### 2. Точный момент краша
- После какого лог-сообщения произошёл краш?
- Что было последнее: "Завершаем worker процессы" или что-то другое?

### 3. Windows Event Viewer
1. Откройте Event Viewer (Просмотр событий)
2. Windows Logs → Application
3. Найдите ошибки около времени краша
4. Скопируйте детали ошибки

### 4. Task Manager
- Остались ли висячие python.exe процессы?
- Сколько их?

## Сравнение с другими режимами

### Один поток
- ✅ Preview работает
- ✅ Стабильно
- ✅ Рекомендуется для CPU

### Pipeline
- ✅ Preview работает
- ✅ OCR в отдельном потоке
- ✅ Полезно при много текстовых знаков

### Process Pool
- ❌ Preview не работает
- ⚠️ Overhead на CPU
- ✅ Полезно только для GPU (будущее)
