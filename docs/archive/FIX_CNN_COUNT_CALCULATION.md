# Исправление расчёта cnn_count

## Проблема

После первого исправления точность классификации стала показывать **0%** вместо правильных значений.

**Причина:** Метод `TrackedSign.cnn_count` считал количество **самого частого класса** в списке CNN результатов, а не количество совпадений с **финальным выбранным типом** (`best_yolo`).

## Пример проблемы

Допустим, знак наблюдался в 10 кадрах:

```python
cnn_results = [
    "3.24",  # кадр 1
    "3.24",  # кадр 2
    "5.16",  # кадр 3
    "5.16",  # кадр 4
    "5.16",  # кадр 5
    "5.16",  # кадр 6
    "5.16",  # кадр 7
    "3.24",  # кадр 8
    "3.24",  # кадр 9
    "3.24",  # кадр 10
]

# После учёта всех факторов (OCR, контекст, геометрия)
best_yolo = "3.24"  # финальный выбранный тип
```

### Старая логика (НЕПРАВИЛЬНО)

```python
def cnn_count(self) -> int:
    """Сколько раз лучший CNN-класс встречается."""
    return self.most_common(self.cnn_results)[1]
```

Результат:
- `most_common(cnn_results)` → `("5.16", 5)`
- `cnn_count` → **5**
- `observation_count` → **10**
- `conf_cnn = 5 / 10` → **0.50** (50%)

**Проблема:** Считается самый частый класс `"5.16"` (5 раз), но финальный тип `"3.24"` встречался тоже 5 раз! При этом финальный тип был выбран именно `"3.24"` на основе других факторов.

Ещё хуже, если самый частый класс вообще не совпадает с финальным:
```python
cnn_results = ["3.24", "5.16", "5.16", "5.16", "3.24"]
best_yolo = "3.24"  # выбран по OCR/контексту

# Старая логика:
cnn_count = 3  # количество "5.16"
obs_count = 5
conf_cnn = 3/5 = 0.60  # НЕПРАВИЛЬНО! должно быть 2/5 = 0.40
```

### Новая логика (ПРАВИЛЬНО)

```python
def cnn_count(self) -> int:
    """Сколько раз финальный тип (best_yolo) встречается в CNN результатах."""
    if not self.cnn_results or not self.best_yolo:
        return 0
    return self.cnn_results.count(self.best_yolo)
```

Результат:
- `self.best_yolo` → `"3.24"`
- `cnn_results.count("3.24")` → **5**
- `cnn_count` → **5**
- `observation_count` → **10**
- `conf_cnn = 5 / 10` → **0.50** (50%) — ПРАВИЛЬНО

Для второго примера:
```python
cnn_results = ["3.24", "5.16", "5.16", "5.16", "3.24"]
best_yolo = "3.24"

# Новая логика:
cnn_count = 2  # количество "3.24"
obs_count = 5
conf_cnn = 2/5 = 0.40  # ПРАВИЛЬНО
```

## Что означает conf_cnn

**`conf_cnn`** (уверенность классификации) показывает, насколько **стабильно** нейросеть распознавала именно тот тип знака, который был выбран как финальный.

- **100%** — нейросеть во всех кадрах выдавала один и тот же класс
- **80%** — в 8 из 10 кадров нейросеть выдавала финальный тип
- **40%** — в 4 из 10 кадров нейросеть выдавала финальный тип (возможно были колебания между классами)
- **0%** — нейросеть ни разу не выдавала финальный тип (он был выбран по OCR/контексту)

## Примеры реальных сценариев

### Сценарий 1: Стабильное распознавание
```python
cnn_results = ["3.24"] * 20  # 20 раз одно и то же
best_yolo = "3.24"
cnn_count = 20
obs_count = 20
conf_cnn = 20/20 = 1.0  # 100% — отлично!
```

### Сценарий 2: Колебания между похожими знаками
```python
cnn_results = ["3.24"] * 12 + ["3.27"] * 8
best_yolo = "3.24"  # выбран как более частый
cnn_count = 12
obs_count = 20
conf_cnn = 12/20 = 0.6  # 60% — средняя уверенность
```

### Сценарий 3: OCR исправил ошибку CNN
```python
cnn_results = ["3.27"] * 15 + ["3.24"] * 5
best_yolo = "3.24"  # OCR прочитал "Минск" → исправил на 3.24
cnn_count = 5
obs_count = 20
conf_cnn = 5/20 = 0.25  # 25% — низкая уверенность CNN, но правильный тип
```

### Сценарий 4: Полностью исправлено OCR
```python
cnn_results = ["5.16"] * 20
best_yolo = "3.24"  # OCR/контекст полностью изменил тип
cnn_count = 0
obs_count = 20
conf_cnn = 0/20 = 0.0  # 0% — CNN не распознал правильно, спасибо OCR
```

## Итоговая уверенность

```python
conf_total = 0.5 * conf_cnn + 0.5 * conf_placement
```

Где:
- **`conf_cnn`** — уверенность классификации (сколько раз CNN выдал финальный тип)
- **`conf_placement`** — уверенность размещения (стабильность трека, snap к OSM, азимут)

Таким образом, даже если CNN плохо распознал (`conf_cnn = 0%`), но знак имеет стабильный трек и хорошо привязался к OSM дороге (`conf_placement = 90%`), итоговая уверенность будет:
```
conf_total = 0.5 * 0.0 + 0.5 * 0.9 = 0.45 (45%)
```

## Как проверить

1. **Запустите обработку видео заново** (старые GeoJSON не обновятся)
2. **Откройте редактор ошибок**
3. **Проверьте уверенность разных знаков:**
   - Знаки с чёткими надписями (3.24 с названием города) — должны иметь **высокую** conf_cnn (70-100%)
   - Знаки без текста, которые CNN хорошо распознал — тоже **высокая** conf_cnn
   - Знаки с колебаниями между похожими типами — **средняя** conf_cnn (40-70%)
   - Знаки, исправленные OCR/контекстом — **низкая** conf_cnn (0-40%)

## Важно

Низкая `conf_cnn` **НЕ означает** что знак распознан неправильно! Это означает что:
- CNN колебался между несколькими классами
- Финальный тип был выбран на основе OCR (текст на знаке)
- Или выбран на основе контекста/геометрии

Для оценки **качества** распознавания нужно смотреть на **`conf_total`** (общую уверенность), которая учитывает и CNN, и размещение.
