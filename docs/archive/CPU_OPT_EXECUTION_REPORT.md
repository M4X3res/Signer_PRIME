## ⚠️ Оставшиеся блоки (3/10 — требуют осторожности)

### БЛОК 5: CPU-потоки (torch/OMP) — НЕ РЕАЛИЗОВАН
**Статус:** ❌ Код не изменён

**Причина:** Максимально рискованный блок:
- История краша `STATUS_STACK_BUFFER_OVERRUN (0xC0000409)`
- Требует ≥30 мин stress-тест на Windows CPU-only
- При малейшем сбое → откат

**Рекомендации:**
1. Начать с `torch.set_num_threads(cpu_count - 1)` только
2. НЕ трогать `OMP_NUM_THREADS` без крайней необходимости
3. Тестировать инкрементально с fallback-флагом
4. Если краш — documented limitation, не пытаться обойти

**Потенциальный эффект:** 2-4× для инференса (если успешно)

### БЛОК 6: Process Pool диагностика — НЕ РЕАЛИЗОВАН
**Статус:** ❌ Баг обнаружен, интеграция не завершена

**Проблема:**
- `ProcessingController._on_process_pool_frame()` не передаёт данные в `SignHandler`
- Результат: пустой GeoJSON
- `config.PROCESSING_MODE` не синхронизируется с `settings.processing_mode`

**Рекомендации:**
- **Вариант A (полная интеграция):** Завершить как в `detector_pool.py`
- **Вариант B (минимум):** Safe-guard — заблокировать выбор в UI на CPU-only

**Эффект:** Корректность, не производительность

### БЛОК 7: ONNX/OpenVINO — НЕ РЕАЛИЗОВАН (опционально)
**Статус:** ⏳ Не начат

**Причина:** Высокая сложность, требует экспорта моделей

**Потенциальный эффект:** 2-4× для YOLO/CNN на Intel CPU (очень высокий)

### БЛОК 8: CPU Performance Mode UI — НЕ РЕАЛИЗОВАН
**Статус:** ⏳ Логика готова, требуется UI

**Что нужно:**
- Авто-детект GPU при старте
