**`ui/widgets/dashboard_page.py`** — метод `FilePickerRow._pick()`

## Почему можно вернуть нативный диалог

### Оригинальная причина использования Qt диалога
В ранних версиях использовали `DontUseNativeDialog` для избежания краша `0xC0000409`.

### Почему краш больше не происходит
Краш был исправлен следующими изменениями:

1. **Переменные окружения в `main.py`:**
   ```python
   os.environ["KMP_DUPLICATE_LIB_OK"] = "TRUE"
   os.environ["OMP_NUM_THREADS"] = "1"
   os.environ["QT_OPENGL"] = "software"
   ```

2. **Безопасное освобождение VideoCapture:**
   - Убран `__del__` с `cv2.VideoCapture.release()`
   - Добавлен явный метод `cleanup()`

3. **closeEvent в MainWindow:**
   - Корректное закрытие всех ресурсов

Эти изменения устранили конфликт между Qt, OpenCV, и torch, поэтому нативный диалог теперь безопасен.

## Qt диалог vs Нативный

### Qt диалог (DontUseNativeDialog)
**Плюсы:**
- Кросс-платформенная консистентность
- Работает одинаково на Windows/Linux/macOS

**Минусы:**
- ❌ Не интегрируется с Windows
- ❌ Нет Quick Access
- ❌ Нет миниатюр
- ❌ Выглядит "чужеродно"
- ❌ Пользователи не привыкли

### Нативный Windows проводник (по умолчанию)
**Плюсы:**
- ✅ Полная интеграция с Windows
- ✅ Привычный интерфейс
- ✅ Все функции Windows (Quick Access, поиск, и т.д.)
- ✅ Миниатюры и иконки

**Минусы:**
- Разный внешний вид на разных ОС (не критично для Windows-only приложения)
