## ✅ Выполненные задачи

### 1. БЛОК A.1 — Pipeline-параллелизм (РЕАЛИЗОВАНО) ⭐⭐⭐

**Проблема:** EasyOCR занимает 200-500ms на один текстовый знак, вызывая провал FPS с 2-3 до 0.1-0.3.

**Решение:**
- Создан `processing/ocr_worker.py` — `OCRWorkerThread` для асинхронной OCR обработки
- Модифицирован `core/detector.py` — добавлен параметр `skip_ocr` и метод `needs_ocr()`
- Модифицирован `processing/detector_thread.py` — поддержка pipeline режима
- OCR выполняется в отдельном потоке параллельно с детекцией следующих кадров
- Интеграция с Settings — переключение "Один поток" / "Pipeline"

**Влияние:** 
- Знаки без текста обрабатываются без замедления
- FPS повышается в 1.5-2 раза при наличии текстовых знаков
- OCR не блокирует основной поток

---

### 2. БЛОК B.4.3 — Progress callback для SaveThread (РЕАЛИЗОВАНО)

**Проблема:** При сохранении GeoJSON с OSM snap UI не зависает (SaveThread работает), но пользователь не видит прогресс. При сотнях знаков процесс может занять минуты.

**Решение:**
- Добавлен параметр `progress_cb` в `FinalHandler.save_result()` (`core/final_handler.py`)
- Прогресс передаётся каждые 5 знаков в `_process_straight_signs()` и при обработке поворотов
- `SaveThread` теперь имеет сигнал `progress = pyqtSignal(int, int, str)` (`ui/main_window.py`)
- Добавлен обработчик `MainWindow._on_save_progress()` который обновляет лог и статус-бар

**Влияние:** Пользователь видит в реальном времени прогресс OSM snap: `"Привязка к дорогам (OSM)... 25/100"`.

---

### 2. БЛОК D.6.4 — Signal processing_finished (РЕАЛИЗОВАНО)

**Проблема:** После завершения обработки карта не обновляется автоматически — пользователь должен вручную нажимать "Перезагрузить".

**Решение:**
- Добавлена функция `emit_processing_finished(sign_count)` в `server/map_server.py`
- Вызывается из `MainWindow._on_save_finished()` после успешного сохранения
- На фронтенде добавлен обработчик `socket.on("processing_finished", ...)` в `templates/map.html`
- При получении сигнала: показывается toast, вызывается `loadAll()` для перезагрузки всех данных карты

**Влияние:** Карта автоматически обновляется после завершения обработки, знаки появляются без действий пользователя.

---

### 3. БЛОК D.6.7 — posMarker visibility (ИСПРАВЛЕНО)

**Проблема:** Маркер текущей позиции создаётся в `initMap()`, но не добавляется на карту до первого события `position` из бэкенда. Если событие не приходит, маркер не виден.

**Решение:**
- `posMarker` теперь добавляется на карту в `initMap()` с `opacity: 0` (скрыт)
- При получении первой позиции в `updatePositionMarker()` устанавливается `setOpacity(1)`
- Логирование активации маркера для отладки

**Влияние:** Маркер позиции становится видимым сразу при первом обновлении координат, без дополнительных проверок `hasLayer`.

### 4. БЛОК C — Настройки: сделать по-настоящему интерактивными (РЕАЛИЗОВАНО ПОЛНОСТЬЮ) ⭐

**Проблема:** Настройки UI не влияют на реальную обработку — все пороги захардкожены в коде.

**Решение:**

#### 4.1. Создан `configs/settings.py`
- Dataclass `AppSettings` с персистентностью через `QSettings`
- Singleton `get_app_settings()`
- Методы `load()`, `save()`, `reset_to_defaults()`

#### 4.2. Интегрировано в `Detector` (`core/detector.py`)
- `__init__(self, settings=None)` принимает настройки
- Пороги `conf_side`, `conf_rube`, `conf_cnn`, `iou_threshold` берутся из settings
- Логирование примененных значений

#### 4.3. Интегрировано в `SignHandler` (`core/sign_handler.py`)
- `__init__(self, settings=None)`
- `NEARBY_SIGN_RADIUS_M` берётся из `settings.dedup_radius_track_m`

#### 4.4. Интегрировано в `FinalHandler` (`core/final_handler.py`)
- `__init__(self, settings=None)`
- `DEDUP_RADIUS_M` и `DEDUP_AZIMUTH_DEG` берутся из settings

#### 4.5. Передача в `DetectorThread` (`processing/detector_thread.py`)
- Настройки загружаются при старте потока
- Передаются в `Detector` и `SignHandler`

#### 4.6. Полная переработка `SettingsPage` (`ui/widgets/settings_page.py`)
- Все контролы подключены к `AppSettings`
- Кнопки "Сохранить" и "Сбросить" работают
- Визуальная обратная связь "✓ Сохранено"
- Настройки персистентны между запусками

**Влияние:** Изменение настроек реально влияет на следующий запуск обработки. Настройки сохраняются между перезапусками приложения.
