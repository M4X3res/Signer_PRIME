```python
class TrackedSign:
    def __init__(self):
        self.yolo_results = []  # Результаты YOLO детектора
        self.cnn_results = []   # Результаты CNN классификатора
    
    def most_common(self, results: list[str]) -> tuple[str, int]:
        """Самый частый элемент списка. Возвращает (name, count)."""
        if not results:
            return ("", 0)
        name, count = Counter(results).most_common(1)[0]
        return (name, count)
    
    @property
    def best_yolo(self) -> str:
        return self.most_common(self.yolo_results)[0]
    
    @property
    def best_cnn(self) -> str:
        return self.most_common(self.cnn_results)[0]
    
    @property
    def cnn_count(self) -> int:
        """Сколько раз лучший CNN-класс встречается."""
        return self.most_common(self.cnn_results)[1]
```

**Файл:** `core/final_handler.py`

## Почему может казаться что не работает?

### 1. Используется старый GeoJSON

**Проблема:** Старые GeoJSON файлы созданы со старым кодом и могут содержать неправильные значения.

**Решение:** Запустите обработку заново.

### 2. Метрики conf_cnn показывают низкие значения

**Это нормально!** `conf_cnn` показывает **стабильность** CNN, а не правильность:

```python
# Пример:
cnn_results = ["3.24", "3.27", "3.24", "5.16", "3.27"]
best_cnn = "3.24" или "3.27"  # самый частый
cnn_count = 2  # количество самого частого
conf_cnn = 2/5 = 40%  # CNN колебался
```

**40% НЕ означает что знак неправильный!** Это означает что CNN колебался между похожими типами.

### 3. Проверка conf_placement вместо conf_cnn

**conf_placement** (GPS уверенность) не влияет на **тип знака**. Она влияет только на размещение.

Даже если `conf_placement` низкая (знак далеко от дороги), тип знака (`best_cnn`) может быть правильным.

### 4. OCR изменяет тип

В оригинальном проекте есть код:
```python
if obj.get_the_most_often(obj.result_yolo)['name'] == '5.8':
    obj.result_CNN = [item for item in obj.result_CNN if item != '5.8']
```

В новом проекте аналогичная логика в `core/final_handler.py`:
```python
if sign.best_yolo == "5.8":
    # ... обработка знака с текстом
```

Это **нормальное поведение** — OCR может корректировать тип на основе прочитанного текста.

## Как проверить что классификация работает

### 1. Запустите обработку ЗАНОВО

Старые GeoJSON не содержат правильных полей!

### 2. Откройте GeoJSON в текстовом редакторе

Найдите любой feature и проверьте:
```json
{
  "type": "Feature",
  "properties": {
    "type": "3.24",  // ← Это best_cnn (финальный тип из CNN)
    "cnn_count": "17",
    "observation_count": "20",
    "conf_cnn": "0.850"
  }
}
```

### 3. Откройте редактор ошибок

Загрузите GeoJSON и проверьте:
- **Колонка "Тип"** — должна показывать правильные типы знаков (3.24, 5.16, и т.д.)
- **Колонка "Уверенность"** — может быть разной (это нормально, см. выше)

### 4. Сравните с кадром

- Нажмите на знак в редакторе
- Посмотрите на кадр справа
- Проверьте соответствует ли тип знака на кадре

**Если тип правильный** — классификация работает!
**Если тип неправильный** — проверьте:
  - Качество видео (размытие, угол)
  - Видимость знака (не закрыт ли)
  - Настройки детектора/классификатора

Реальная проблема классификации — это когда:

1. **Тип знака неправильный** (3.24 вместо 5.16)

   - Проверьте что модели загружаются корректно
   - Проверьте логи обработки

3. **Типы знаков странные** ("unknown", пустые)
   - Проверьте что CNN модель работает
   - Проверьте `cnn_results` в логах
