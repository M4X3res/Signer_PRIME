# Возврат к старой логике cnn_count (2026-07-10 11:33)

## Проблема

После изменения `cnn_count` для подсчёта совпадений с финальным типом `best_yolo`, классификация стала работать **некорректно**.

## Что было изменено (11:06) — ОТМЕНЕНО

```python
@property
def cnn_count(self) -> int:
    """Сколько раз финальный тип (best_yolo) встречается в CNN результатах."""
    if not self.cnn_results or not self.best_yolo:
        return 0
    return self.cnn_results.count(self.best_yolo)
```

**Проблема этого подхода:**
- Если финальный тип был выбран по OCR/контексту (а не как самый частый CNN класс), то `cnn_count` становится малым
- Это искажает метрику `conf_cnn = cnn_count / observation_count`
- Получается что знаки с хорошим CNN распознаванием показывают низкую уверенность

## Возврат к оригинальной логике

```python
@property
def cnn_count(self) -> int:
    """Сколько раз лучший CNN-класс встречается."""
    return self.most_common(self.cnn_results)[1]
```

**Что означает теперь:**
- `cnn_count` — количество раз, когда **самый частый** класс встречался в CNN результатах
- `conf_cnn = cnn_count / observation_count` — насколько **стабильно** CNN распознавал (независимо от финального типа)

## Почему оригинальная логика правильная

### Пример 1: CNN стабильно распознавал, OCR исправил

```python
cnn_results = ["5.16", "5.16", "5.16", "5.16", "5.16"]  # CNN всегда выдавал 5.16
best_yolo = "3.24"  # OCR прочитал "Минск" и исправил на 3.24

# С новой логикой (НЕПРАВИЛЬНО):
cnn_count = 0  # количество "3.24" в cnn_results
conf_cnn = 0 / 5 = 0%  # Показывает 0%, хотя CNN был СТАБИЛЕН!

# Со старой логикой (ПРАВИЛЬНО):
cnn_count = 5  # самый частый класс "5.16"
conf_cnn = 5 / 5 = 100%  # Показывает 100% — CNN стабильный
```

**Интерпретация:**
- `conf_cnn = 100%` — CNN был уверен и стабилен (пусть и ошибался)
- OCR правильно исправил ошибку CNN
- Низкий `conf_cnn` должен означать "CNN колебался", а не "OCR исправил"

### Пример 2: CNN колебался между классами

```python
cnn_results = ["3.24", "3.27", "3.24", "5.16", "3.27"]
best_yolo = "3.24"  # Выбран как наиболее подходящий

# Со старой логикой (ПРАВИЛЬНО):
most_common = "3.27" (2 раза) или "3.24" (2 раза)
cnn_count = 2
conf_cnn = 2 / 5 = 40%  # Правильно показывает нестабильность
```

## Что означает conf_cnn

### Оригинальная логика (восстановлено)
```
conf_cnn = (количество раз самого частого CNN класса) / (всего наблюдений)
```

**Показывает:** Насколько **стабильно** CNN распознавал (любой класс)

- **100%** — CNN всегда выдавал один и тот же класс (стабильно)
- **60%** — В 6 из 10 кадров CNN выдавал один класс, в остальных — другие (средняя стабильность)
- **30%** — CNN сильно колебался между разными классами (нестабильно)

**Это метрика СТАБИЛЬНОСТИ CNN, не корректности!**

### Предыдущая логика (11:06-11:33, ОТМЕНЕНО)
```
conf_cnn = (количество раз финального типа) / (всего наблюдений)
```

**Проблема:** Эта метрика смешивает два разных понятия:
- Стабильность CNN
- Соответствие CNN результата финальному типу (который мог быть выбран по OCR)

## Правильная интерпретация метрик

### conf_cnn (стабильность CNN)
- **Высокая (>70%)** — CNN стабильно распознавал один класс
- **Средняя (40-70%)** — CNN колебался между 2-3 классами
- **Низкая (<40%)** — CNN сильно колебался между разными классами

**Не показывает:** Правильность финального типа (за это отвечает проверка OCR/контекста)

### conf_placement (качество размещения)
- Стабильность трека
- OSM snap
- Азимут
- Длина трека

### conf_total (общая уверенность)
```
conf_total = 0.5 * conf_cnn + 0.5 * conf_placement
```

**Показывает:** Комбинацию стабильности CNN и качества размещения

## Примеры с правильной интерпретацией

### Пример 1: Стабильный CNN, правильно исправлен OCR

```python
cnn_results = ["5.16"] * 20
best_yolo = "3.24"  # OCR прочитал "Минск"

conf_cnn = 100%  # CNN стабилен
conf_placement = 85%  # Хороший GPS
conf_total = 92.5%  # Высокая общая уверенность

# Интерпретация:
# ✅ CNN стабильно распознавал (пусть и не тот класс)
# ✅ GPS точный
# ✅ OCR исправил тип на правильный
# → Высокое качество данных, знак правильный
```

### Пример 2: Нестабильный CNN

```python
cnn_results = ["3.24", "3.27", "5.16", "3.24", "3.27"]
best_yolo = "3.24"

conf_cnn = 40%  # CNN колебался (max 2 из 5)
conf_placement = 60%  # Средний GPS
conf_total = 50%  # Средняя уверенность

# Интерпретация:
# ⚠️ CNN нестабилен — знак плохо виден или спорный
# ⚠️ GPS средний
# → Проверить внимательно
```

### Пример 3: Стабильный CNN, стабильный без OCR

```python
cnn_results = ["3.24"] * 15
best_yolo = "3.24"

conf_cnn = 100%  # CNN стабилен
conf_placement = 90%  # Отличный GPS
conf_total = 95%  # Очень высокая уверенность

# Интерпретация:
# ✅ CNN стабильно и правильно распознал
# ✅ GPS отличный
# → Очень высокое качество, можно доверять
```

## Вывод

**Оригинальная логика правильная, потому что:**

1. ✅ `conf_cnn` показывает **стабильность CNN**, а не соответствие финальному типу
2. ✅ Высокая `conf_cnn` означает что CNN был уверен (даже если OCR потом исправил)
3. ✅ Низкая `conf_cnn` означает что CNN колебался (знак плохо виден или спорный)
4. ✅ Это помогает отфильтровать знаки с плохим качеством видео

**Финальный тип** выбирается умным алгоритмом (CNN + OCR + контекст), поэтому:
- Если `conf_cnn` высокая — CNN был уверен
- Если OCR изменил тип — это хорошо, OCR исправил ошибку CNN
- Общая `conf_total` всё равно будет высокой (стабильный CNN + хороший GPS)
