## Что было сделано

### Архитектурное решение

Реализован **pipeline-параллелизм** по стадиям обработки:

```
VideoReaderThread → frame_queue
        ↓
DetectorThread (основной поток):
  - YOLO side-detect (поиск bbox)
  - YOLO rube классификация
  - CNN fine классификация
  - Знаки БЕЗ текста → ready
  - Знаки С текстом → отправка в OCRWorkerThread
        ↓
OCRWorkerThread (отдельный поток):
  - EasyOCR.readtext (самая медленная операция)
  - Результат → callback в DetectorThread
        ↓
SignHandler.check_the_data_to_add()
  - Трекинг знаков (строго последовательный)
```

### Ключевые преимущества:

1. **OCR не блокирует основной поток** — пока OCR работает, основной поток обрабатывает следующие кадры
2. **Знаки без текста обрабатываются быстро** — не ждут OCR
3. **Порядок кадров сохраняется** — трекинг работает корректно
4. **Graceful degradation** — если OCR Worker перегружен, знаки остаются без текста, но не теряются

## Производительность

**Ожидаемый прирост:**
- FPS повышается в 1.5-2 раза при текстовых знаках
- Знаки без текста: без изменений (~300-500ms/кадр)
- Знаки с текстом: детекция быстро, OCR параллельно
