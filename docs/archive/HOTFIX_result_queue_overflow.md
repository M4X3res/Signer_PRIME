# HOTFIX: Зависание на "result_queue переполнена"

**Дата:** 24 августа 2026, 15:57  
**Проблема:** Программа зависала при обработке длинных видео с сообщением `result_queue переполнена!`

---

## Причина проблемы

1. **Переполнение очереди:** Размер `result_queue` был 500 знаков
2. **Блокирующий put:** При переполнении код делал `self._result_q.put(sign, block=True)` — бесконечное ожидание
3. **Редкое чтение:** Очередь читалась только в конце обработки (`_save_results()`), а не во время

При длинном видео (>500 знаков) очередь переполнялась, и поток зависал в бесконечном ожидании освобождения места.

---

## Решение

### 1. Увеличен размер очереди (500 → 5000)
**Файл:** `processing/processing_controller.py:51`

```python
RESULT_QUEUE_SIZE = 5000  # знаков в буфере (было 500)
```

### 2. Неблокирующий put с пропуском
**Файл:** `processing/detector_thread.py:409-420`

```python
for sign in self._sign_handler.result_signs:
    try:
        self._result_q.put(sign, timeout=0.1)  # Было: timeout=1.0
    except queue.Full:
        # Было: self._result_q.put(sign, block=True) — бесконечное ожидание
        # Стало: пропускаем с предупреждением и break
        logger.warning(f"result_queue переполнена! Пропуск знака {sign.best_cnn}")
        break  # Выходим из цикла
```

**Важно:** Знаки НЕ ТЕРЯЮТСЯ! Они остаются в `sign_handler.turns` и будут обработаны через `get_turn_data()` в конце.
