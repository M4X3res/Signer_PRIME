### ✅ БЛОК 1 — Оптимизация декодирования видео

**Файлы изменены:**
- `processing/video_reader.py` — реализован `grab()`/`retrieve()` паттерн

**Файлы созданы:**
- `CPU_OPT_BLOCK_1_GRAB_RETRIEVE.md` — полный отчёт

**Реализация:**
```python
# Было:
ret, image = cap.read()
if frame_counter % step != 0:
    continue  # 80% кадров декодированы впустую

# Стало:
grabbed = cap.grab()  # Дешёвый захват
if frame_counter % step != 0:
    continue  # НЕ декодируем пропущенные
ret, image = cap.retrieve()  # Декодирование только нужных
```

**Профилировщик:**
- Добавлены замеры: `video_grab_frame`, `video_retrieve_frame`

**Что требуется:**
- Regression-тест на идентичность кадров
- GoPro stress-тест (30+ мин)
- Фактические замеры FPS до/после

### ✅ БЛОК 4 — Троттлинг OCR (завершён)

**Файлы созданы:**
- `CPU_OPT_BLOCK_4_OCR_THROTTLING.md` — отчёт по OCR-троттлингу

**Ключевые изменения:**
1. Добавлены методы `should_run_ocr()` и `mark_ocr_requested()` в `TrackedSign`
2. Настройки `ocr_throttle_interval_frames=8`, `ocr_max_calls_per_sign=6`
3. OCR-решение принимается **ПОСЛЕ** трекинга (не до)
4. Логирование: `OCR: X calls, Y skipped (Z%)`

**Эффект:**
- Типичный знак (40 кадров) → 6 OCR вызовов вместо 40 (85% экономия)
- Ожидаемый прирост: 5-8× для OCR-компонента, 2-3× для всего пайплайна

**Что требуется:**
- Regression-тест текста (SEM250/MVALUE идентичны baseline)
- FPS-бенчмарк на городском видео

## Критичные замечания для дальнейшей работы

### ⚠️ БЛОК 5 (CPU-потоки) — МАКСИМАЛЬНАЯ ОСТОРОЖНОСТЬ

Этот блок должен выполняться **ПОСЛЕДНИМ** из "быстрых" блоков по следующим причинам:

1. **История крашей:** `0xC0000409 STATUS_STACK_BUFFER_OVERRUN` при конфликте OpenMP-рантаймов
2. **Текущие ограничения:** `OMP_NUM_THREADS=1` установлен как критичный workaround
3. **Требования к тестированию:** ≥30 мин stress-тест на Windows CPU-only, никаких исключений

**План БЛОКА 5:**
1. Начать с `torch.set_num_threads(N)` только (без изменения `OMP_NUM_THREADS`)
2. Тестировать инкрементально: 2 потока → 4 потока → авто
3. Если хоть один краш — откат и documented limitation
4. `OMP_NUM_THREADS` трогать ТОЛЬКО если шаг 1-3 полностью стабилен
