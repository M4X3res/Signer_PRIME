### Часть 1, Шаг 1: Исправление бага `_attach_unmatched`

**Проблема**: Сравнение `raw_vec` (сырое пиксельное расстояние) с `distance` (adjusted с учётом SAME_TYPE_BONUS = -50). При совпадении типа знака (основной случай): `abs(raw_vec - (raw_vec - 50)) = 50 > 30` → условие никогда не срабатывало.

**Решение**: 
- Восстанавливаем raw distance из adjusted: `raw_distance = adjusted_distance + SAME_TYPE_BONUS`
- Сравниваем raw с raw: `abs(raw_vec - raw_distance) <= 30`

**Файлы**:
- `core/sign_handler.py`: метод `_attach_unmatched()` исправлен
- `tests/test_attach_unmatched_fix.py`: 2 регрессионных теста (оба проходят)

**Результат**: ✅ Тесты проходят, механизм fallback-прикрепления теперь работает.

### Часть 1, Шаги 2-3: Адаптивные пороги для gap и DIFF_FRAMES_REMOVE

**Проблема**: Пороги `gap < 7` и `DIFF_FRAMES_REMOVE = 5` жёстко зашиты, но реальный шаг между обработанными кадрами может достигать `FRAME_STEP(5) × current_skip(до 5) = 25` из-за адаптивного skip в `DetectorThread._calc_skip_interval()`.

**Требуется**:
1. Прокинуть текущий `effective_skip` (`config.FRAME_STEP × _current_skip`) из `DetectorThread` в `config` или `SignHandler`
2. Сделать пороги зависимыми от эффективного skip: 
   ```python
   max_match_gap = base_match_gap × max(1, effective_skip) × safety_margin(1.5)
   ```
3. Вынести базовые константы в `AppSettings`:
   - `sign_match_max_gap_frames` (дефолт ~30)
   - `sign_remove_after_gap_frames` (дефолт ~30)
4. Аналогично для `FinalHandler.duplicate_time_overlap_frames`

**Риски**: Высокий — затрагивает core логику трекинга. Требуется:
- Тщательное тестирование на видео с разными профилями скорости
- Калибровка параметров на реальных данных
- Проверка что не появляется обратная проблема (ошибочное слияние разных знаков)
