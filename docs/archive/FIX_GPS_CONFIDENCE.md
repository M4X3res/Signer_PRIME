# Исправление GPS уверенности (conf_placement)

## Проблема

После исправления `conf_cnn`, GPS уверенность всё ещё показывала неправильные значения, потому что **не использовала готовые данные из GeoJSON**.

### Что было не так

В `ui/widgets/error_editor_page.py` функция `SignRecord._calc_gps_confidence()`:
1. **Не использовала** готовое значение `conf_placement` из GeoJSON
2. Вместо этого **пересчитывала** уверенность приближённо по координатам
3. **Не учитывала** важные факторы:
   - OSM snap (привязка к дороге)
   - Азимут GPX vs OSM
   - Детальную стабильность трека (pixel координаты)

### Что сохраняется в GeoJSON

В `core/sign.py` метод `calculate_confidence()` рассчитывает:

```python
conf_placement = (
    0.30 * track_stability    # стабильность pixel координат
    + 0.25 * length_score      # количество кадров
    + 0.25 * snap_score        # качество привязки к OSM дороге
    + 0.20 * azimuth_score     # соответствие азимутов GPX/OSM
)
```

Это **точная метрика**, которая учитывает:
- **Track stability** — разброс pixel_x по кадрам (чем меньше — тем стабильнее)
- **Length score** — количество наблюдений (4 кадра = 0%, 20+ = 100%)
- **OSM snap** — расстояние до ближайшей дороги (0-5м = 100%, >30м = 0%)
- **Azimuth delta** — расхождение GPX курса и направления дороги OSM (0° = 100%, >45° = 0%)

### Что делал старый код

```python
def _calc_gps_confidence(self) -> float:
    # НЕ использует готовое conf_placement из GeoJSON!
    
    azimuth_score = 0.3 if has_azimuth else 0.0
    obs_score = min(0.3, obs_count / 30.0)
    
    # Только грубый разброс координат
    lat_range = max(lats) - min(lats)
    lon_range = max(lons) - min(lons)
    stability = 1.0 - min(1.0, (lat_range + lon_range) / 0.002)
    stability_score = stability * 0.4
    
    return azimuth_score + obs_score + stability_score
```

**Проблемы:**
- ❌ Не учитывает OSM snap (самый важный фактор!)
- ❌ Не учитывает расхождение азимутов
- ❌ Грубо считает разброс GPS координат (не учитывает pixel стабильность)
- ❌ Пересчитывает вместо использования готовых данных

## Решение

### 1. Использование готового conf_placement

**Файл:** `ui/widgets/error_editor_page.py`

```python
def _calc_gps_confidence(self) -> float:
    """
    Уверенность размещения (placement): качество GPS + OSM snap + азимут.
    
    Сначала пытаемся взять готовое значение conf_placement из properties.
    Если его нет — рассчитываем приближённо на основе доступных данных.
    """
    # Пытаемся взять готовое значение (предпочтительно)
    conf_placement_str = self.props.get("conf_placement", "")
    if conf_placement_str:
        try:
            return float(conf_placement_str)
        except (ValueError, TypeError):
            pass
    
    # Если нет готового значения — fallback на приближённый расчёт
    # (менее точно, т.к. не учитывает OSM snap и детальную стабильность)
    # ... старый код ...
```

### 2. Использование готового conf_total

```python
# Общая уверенность
# Пытаемся взять готовое значение conf_total из GeoJSON (предпочтительно)
conf_total_str = self.props.get("conf_total", "")
if conf_total_str:
    try:
        self.total_confidence = float(conf_total_str)
    except (ValueError, TypeError):
        self.total_confidence = 0.5 * self.confidence + 0.5 * self.gps_confidence
else:
    # Если нет готового значения — рассчитываем (50/50 как в core/sign.py)
    self.total_confidence = 0.5 * self.confidence + 0.5 * self.gps_confidence
```

### 3. Правильная формула total_confidence

Обновлены веса для соответствия `core/sign.py`:
```python
# БЫЛО:
self.total_confidence = (self.confidence + self.gps_confidence) / 2.0

# СТАЛО:
self.total_confidence = 0.5 * self.confidence + 0.5 * self.gps_confidence
# (математически то же самое, но явно показывает веса 50/50)
```

- ✅ **Низкий** (<40%) — проблемы с GPS или знак далеко от дороги

## OSM Snap — что это?

**OSM snap** — это привязка координат знака к ближайшему ребру дороги в OpenStreetMap.

### Зачем нужен?

GPS имеет погрешность 5-15 метров. Без snap:
- Знак может быть отображён в поле рядом с дорогой
- Координаты "гуляют" по разные стороны дороги
- Сложно понять к какой именно дороге относится знак

С snap:
- Знак "прикрепляется" к ближайшему ребру дороги
- Координаты точные (на линии дороги)
- Понятно направление (азимут дороги)

### Как оценивается?

```python
if snap_dist_m <= 5:
    snap_score = 1.0      # Отлично - знак точно у дороги
elif snap_dist_m <= 30:
    snap_score = ...      # Линейная интерполяция
else:
    snap_score = 0.0      # Плохо - знак далеко от дороги
```

**Примеры:**
- 2м от дороги → 100% (идеально)
- 10м от дороги → 80% (хорошо)
- 20м от дороги → 40% (средне, возможно знак сбоку)
- 40м от дороги → 0% (плохо, возможно ошибка GPS или знак не у дороги)

## Как проверить

### 1. Перезапустите обработку

⚠️ Старые GeoJSON не содержат `conf_placement` — требуется новая обработка!

### 2. Откройте редактор ошибок

Загрузите новый GeoJSON и проверьте:

**Знаки у дороги (близкий snap):**
- conf_placement должна быть **высокая** (>70%)
- Цвет: зелёный

**Знаки далеко от дороги:**
- conf_placement должна быть **низкая** (<40%)
- Цвет: красный
- Это может быть нормально для знаков на парковках, внутренних территориях

**Знаки со стабильным треком:**
- Даже при среднем snap, conf_placement будет >50% если трек стабильный

### 3. Проверьте GeoJSON

Откройте в текстовом редакторе:
```json
{
  "properties": {
    "conf_cnn": "0.850",
    "conf_placement": "0.782",
    "conf_total": "0.816",
    "snap_distance": "4.2",
    "azimuth_delta": "8.5"
  }
}
```

Редактор должен показать:
- Confidence (CNN): 85%
- GPS confidence: 78%
- Total: 81%

## Важно

### Низкая conf_placement — не всегда ошибка!

**Возможные причины:**
1. ✅ **Знак не у главной дороги** (парковка, внутренняя территория)
2. ✅ **OSM карта неполная** (дорога не отмечена в OSM)
3. ⚠️ **Проблема GPS** (большой разброс координат)
4. ⚠️ **Ошибка детекции** (знак распознан не там где нужно)

**Как различить:**
- Посмотрите на кадр — виден ли знак, где он?
- Проверьте карту — есть ли дорога в OSM?
- Если на кадре всё хорошо, но low conf_placement — возможно просто нет дороги в OSM

### Общая уверенность — главная метрика!

**conf_total** = 50% CNN + 50% placement

Это **балансированная** оценка:
- Если CNN уверен, но GPS плохой → средняя оценка (проверить)
- Если GPS хороший, но CNN не уверен → средняя оценка (OCR мог исправить)
- Если оба высокие → высокая оценка (скорее всего правильно)
- Если оба низкие → низкая оценка (внимательно проверить!)
