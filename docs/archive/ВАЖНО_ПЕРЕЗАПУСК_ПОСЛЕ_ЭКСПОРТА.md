# ⚠️ ВАЖНО: Перезапуск приложения после переэкспорта моделей

## Проблема

После переэкспорта ONNX моделей (с динамическим размером) приложение продолжает использовать **старые модели из кэша** в worker процессах.

## Почему это происходит?

1. **ProcessPoolExecutor переиспользует процессы**
   - Worker процессы остаются живыми между запусками обработки
   - Модели загружаются один раз и кэшируются в памяти процесса
   
2. **Singleton pattern в worker процессе**
   ```python
   # Singleton детектор для процесса (загружается один раз)
   if not hasattr(_worker_process_frame, '_detector'):
       _worker_process_frame._detector = Detector()
   ```
   
3. **Модели не перезагружаются автоматически**
   - При втором запуске обработки используются те же worker процессы
   - Детектор не создаётся заново, используется кэшированный
   - ONNX модели остаются старыми (с фиксированным размером)

## ✅ Решение

### После переэкспорта моделей ОБЯЗАТЕЛЬНО:

1. **Закройте приложение полностью** (не просто остановите обработку)
2. **Запустите приложение заново**
3. Начните обработку

## Как проверить, что используются новые модели?

### 1. Проверьте размер модели:
```bash
.venv\Scripts\python.exe check_onnx_input_size.py
```

**Ожидается:**
```
Shape: batch 3 height width  # ✅ Динамический размер
```

**НЕ должно быть:**
```
Shape: 1 3 960 960  # ❌ Фиксированный размер
```

### 2. Проверьте дату модификации файлов:

```bash
dir CNN_side\best.onnx
dir small_models\rude.onnx
```

Дата модификации должна соответствовать времени переэкспорта.

### 3. Проверьте логи при запуске:

После перезапуска приложения и начала обработки в логах **НЕ ДОЛЖНО быть:**
```
ERROR: Got invalid dimensions for input: images
Got: 608 Expected: 960
```

**ДОЛЖНО быть:**
```
[Worker] Загрузка моделей детектора...
[Worker] Модели загружены
[sign_models] Загружена ONNX-модель: best.onnx (CPU mode)
```
