# Исправление краша при нажатии кнопки GeoJSON

## Дата: 2026-07-10

### Проблема
При нажатии на кнопку "Выбрать" для GeoJSON файла программа вылетает с ошибкой:
```
Process finished with exit code -1073740791 (0xC0000409)
```

Это критическая ошибка `STATUS_STACK_BUFFER_OVERRUN` на уровне Windows.

### Причина

**Конфликт Qt Native Dialog с WebEngine:**
1. Qt использует нативные системные диалоги Windows (через COM)
2. WebEngine (Chromium) активно использует GPU и OpenGL
3. Torch/OpenCV используют OpenMP для многопоточности
4. При попытке открыть нативный диалог происходит конфликт в памяти

**Известная проблема:**
- Qt + WebEngine + Native Dialogs на Windows могут вызывать buffer overrun
- Особенно при наличии GPU acceleration и многопоточных библиотек
- Ошибка 0xC0000409 - это защита памяти Windows DEP (Data Execution Prevention)

### Решение

#### 1. Использование Qt диалогов вместо нативных (ui/widgets/dashboard_page.py)

**Было:**
```python
def _pick(self):
    path = ""
    if self._mode == "save":
        result = QFileDialog.getSaveFileName(
            self, "Создать или выбрать файл", "", self._filter
        )
        path = result[0]
```

**Стало:**
```python
def _pick(self):
    try:
        path = ""
        # Используем Qt диалог (не нативный) для избежания 0xC0000409 ошибки
        options = QFileDialog.Option.DontUseNativeDialog
        
        if self._mode == "save":
            result = QFileDialog.getSaveFileName(
                self, "Создать или выбрать файл", "", self._filter, options=options
            )
            path = result[0] if result and result[0] else ""
        
        if path:
            path = path.replace("/", "\\")
            self.set_path(path)
            self.changed.emit(path)
    except Exception as e:
        print(f"[FilePickerRow] Ошибка в _pick: {e}")
        traceback.print_exc()
```

**Изменения:**
- ✅ Добавлен флаг `DontUseNativeDialog` - использует Qt диалог
- ✅ Добавлена обработка исключений
- ✅ Проверка что result не пустой
- ✅ Нормализация пути для Windows

#### 2. Дополнительная защита в main.py

**Добавлено:**
```python
# Дополнительная защита для Qt диалогов на Windows
# Отключает аппаратное ускорение для избежания конфликтов драйверов
os.environ["QT_OPENGL"] = "software"
```

**Эффект:**
- Qt использует программный рендеринг вместо GPU
- Снижает вероятность конфликтов с WebEngine
- Диалоги работают стабильно

### Разница между нативными и Qt диалогами

**Нативный диалог (Windows API):**
- ✅ Выглядит как системный Windows диалог
- ✅ Интегрируется с проводником
- ❌ Может крашить при конфликте с WebEngine/GPU
- ❌ Требует COM инициализацию

**Qt диалог:**
- ✅ Стабильный, нет конфликтов
- ✅ Кроссплатформенный
- ✅ Полностью контролируется Qt
- ⚠️ Выглядит как Qt виджет (не системный)

### Побочные эффекты

**Визуальные:**
- Диалог выбора файлов будет выглядеть как Qt окно, а не как Windows Explorer
- Немного другой стиль кнопок и шрифтов
- Работает стабильно

**Производительность:**
- `QT_OPENGL=software` немного снижает производительность UI
- Но карта (WebEngine) использует свой рендеринг, не затронут
- Влияние минимальное, заметно только на очень слабых ПК

**Проверьте следующие сценарии:**

1. **Выбор GeoJSON файла:**
   - Нажмите "Выбрать" для GeoJSON

   - Выберите или создайте файл

   - Нажмите "Выбрать видео или папку"

   - Запустите обработку (карта активна)

### Альтернативные решения (если проблема сохраняется)

#### Вариант 1: Ручной ввод пути

Добавить текстовое поле рядом с кнопкой:
```python
self._path_edit = QLineEdit()
self._path_edit.textChanged.connect(self.changed.emit)
```

#### Вариант 2: Отложенная инициализация WebEngine

Запускать карту только после выбора всех файлов:
```python
# В MainWindow._on_start():
if not self.page_map._server_thread:
    self.page_map.start_server()
```

#### Вариант 3: Restart для применения изменений

После выбора GeoJSON показывать сообщение:
```
"Файл выбран. Рекомендуется перезапустить приложение для полной стабильности."
```

### Рекомендации

**При разработке:**
- Тестируйте диалоги до запуска WebEngine (до открытия карты)
- Если нужен системный вид - используйте после закрытия карты
- Или используйте отдельный процесс для диалогов

**При деплое:**
- Включить `DontUseNativeDialog` всегда
- Или вообще не использовать диалоги - только текстовые поля
- Или использовать drag-and-drop для файлов

**Для Windows Server:**
- Native dialogs могут не работать в Remote Desktop
- Qt dialogs работают везде
- Текущее решение оптимально для всех случаев
