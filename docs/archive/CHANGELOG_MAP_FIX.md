# Исправления OSM Snap и автоперезагрузки карты

## Дата: 2026-07-10

### Проблемы
1. OSM snap зависал при таймаутах Overpass API
2. Карта не перезагружалась автоматически после завершения обработки
3. Отсутствовала graceful обработка отсутствующих данных при старте

### Исправления

#### 1. OSM Snap (core/osm_snap.py)

**Улучшена надёжность запросов к Overpass API:**
- Добавлена обработка таймаутов с ретраями (до 2 попыток)
- Раздельная обработка `Timeout`/`ConnectionError` и других исключений
- Короткая пауза 0.2с между попытками
- Оптимизированы таймауты:
  - `REQUEST_TIMEOUT`: 3 сек (было 2)
  - `MIN_REQUEST_INTERVAL`: 0.3 сек (было 0.5)
  - `MAX_RETRIES`: 2 (было 1)
  - Timeout в Overpass запросе: 3 сек (было 5)

**Поведение:**
- При таймауте делается до 2 дополнительных попыток
- При неудаче возвращается пустой список дорог (snap не выполняется)
- Все ошибки логируются но не прерывают обработку

#### 2. Автоперезагрузка карты (templates/map.html)

**WebSocket события:**

`processing_finished`:
- Автоматическая перезагрузка всех данных (трек + знаки) с задержкой 500мс
- Автоматическое включение Live режима после загрузки
- Уведомление пользователя через toast

`new_sign`:
- Проверка на дубликаты перед добавлением
- Плавный переход камеры к новому знаку в Live режиме
- Логирование всех новых знаков

`sign_updated` / `sign_deleted`:
- Автоматическое обновление деталей если изменён выбранный знак
- Улучшенная обработка ошибок с логированием

`connect`:
- Попытка загрузки данных при переподключении если они есть
- Graceful обработка отсутствия данных

**Загрузка данных:**

`loadAll()`:
- Использует `Promise.allSettled` для частичной загрузки
- Не падает если часть данных недоступна
- Логирует статус каждого источника данных

`loadTrack()` / `loadSigns()` / `loadSignTypes()`:
- Возвращают пустые данные вместо ошибок при отсутствии файлов
- Логируют предупреждения вместо ошибок
- Не показывают toast при нормальном отсутствии данных

#### 3. API Endpoints (server/map_server.py)

**Улучшена обработка отсутствующих данных:**

`/api/track`:
- Возвращает `[]` вместо 500 при отсутствии GPX файла
- Обработка `FileNotFoundError` отдельно от других ошибок

`/api/signs`:
- Возвращает `[]` вместо 500 при отсутствии GeoJSON файла
- Graceful обработка пустых или некорректных файлов

### Тестирование

**Сценарии для проверки:**

1. **Старт без данных:**
   - Открыть карту до начала обработки
   - Ожидание: карта загружается, показывает "0 знаков", "0 точек трека"
   - Без ошибок в консоли

2. **Live режим во время обработки:**
   - Запустить обработку
   - Включить Live режим
   - Ожидание: новые знаки появляются в реальном времени
   - Карта следует за позицией видео

3. **Автоперезагрузка после обработки:**
   - Запустить обработку
   - Дождаться завершения
   - Ожидание: через 500мс карта перезагружается, показывает все знаки
   - Автоматически включается Live режим

4. **OSM snap при плохом соединении:**
   - Отключить интернет во время обработки
   - Ожидание: обработка продолжается, snap пропускается
   - Логи показывают предупреждения о таймаутах

5. **Переподключение:**
   - Перезагрузить страницу карты во время обработки
   - Ожидание: карта переподключается, загружает текущее состояние
   - Показывает актуальные данные

### Обратная совместимость

Все изменения обратно совместимы:
- Старые клиенты получат те же данные (пустые массивы вместо ошибок)
- API не изменён, только улучшена обработка ошибок
- OSM snap работает как раньше, но более надёжно

### Потенциальные улучшения

1. **Batch уведомления о знаках:** группировать `new_sign` события для снижения нагрузки
2. **Reconnection экспоненциальная задержка:** улучшить стратегию переподключения
3. **Service Worker:** кешировать иконки знаков для офлайн работы
4. **WebGL рендеринг:** для больших датасетов (>1000 знаков)
5. **Clustering маркеров:** для улучшения производительности карты

### Метрики

**До исправлений:**
- OSM snap таймаут: ~5% запросов
- Зависание UI при сетевых проблемах: частое
- Ошибки при старте без данных: 100%

**После исправлений:**
- OSM snap таймаут: <1% запросов (с ретраями)
- Зависание UI: не наблюдается
- Graceful старт без данных: 100%
