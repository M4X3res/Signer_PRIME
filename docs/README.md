# Signer PRIME

Signer PRIME — Windows-приложение на PyQt6 для поиска дорожных знаков на видео, привязки обнаружений к GPS-треку и ручной проверки результата.

## Установка и запуск

Требуется Windows, Python 3.10+ и зависимости из `requirements.txt`:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Для воспроизведения исходных файлов карте нужен `ffmpeg` в `PATH`. Приложение может подготовить кэш WebM для браузерного плеера самостоятельно.

## Рабочий процесс

1. На странице обработки выберите видео, GeoJSON/GPS-трек и параметры моделей.
2. Запустите обработку. Результаты сохраняются в GeoJSON, а промежуточные кадры и кэш зависят от настроек проекта.
3. В редакторе ошибок выберите обнаружение, проверьте кадр, тип, текст и азимут. Нажмите «Применить» для текущего знака и «Сохранить» для записи GeoJSON.
4. На карте выберите знак для просмотра видео, позиции и участка GPS-трека.

## Карта и редактор

Для подготовки данных для ГИС «Панорама» включите в **Настройки → Расширенные → GPS и координаты** пункт **«Азимут перпендикулярно дороге (ГИС «Панорама»)»** и сохраните настройки. При новой обработке азимут направляется наружу от дороги: справа по ходу машины — направление дороги +90°, слева — −90°. Направление линии OSM согласуется с направлением движения; без привязки к OSM используется направление GPS-трека. Настройка выключена по умолчанию и не изменяет уже сохранённые результаты. Координаты знаков и правила удаления дубликатов остаются прежними.

Готовый результат можно открыть кнопкой **«Открыть обработанный GeoJSON»** на странице запуска. Файл сразу загружается в редактор и на карту. Для кадров видео и участка GPX дополнительно выберите соответствующую папку и трек; без них доступны карта и редактирование свойств знаков.

Карта загружается из `templates/map.html` внутри `QWebEngineView`; сервер карты находится в `server/map_server.py` и работает локально.

Основные возможности карты:

- видео-клип вокруг обнаружения и режим полного видео;
- ручное перетаскивание знака и изменение азимута: зажмите знак и прокрутите колесо, используйте ручку компаса или введите угол под знаком;
- участок GPS-трека до и после обнаружения со стрелками направления;
- создание и редактирование знаков с визуальным выбором типа;
- кэширование подготовленных WebM в `.signer_clip_cache` рядом с исходными видео.

### Локальные подложки

На карте нажмите **«Открыть подложку…»**. Поддерживаются JPEG с JGW/WLD и PRJ,
TIF/GeoTIFF, несколько SHP с PRJ или ZIP с несколькими слоями. Для файла без PRJ
укажите код EPSG. JPEG без JGW требует точных границ в градусах WGS84 и ориентации
севером вверх; положение по одному изображению автоматически не угадывается.

GeoTIFF использует встроенную геопривязку; обычный TIF — TFW/PRJ или введённые границы.
Поддерживаются 8-битные растры: серые, RGB, RGBA и TIFF с палитрой.
Одна кнопка **«Выбрать файлы»** позволяет выбрать сразу несколько файлов.
В расширенных настройках **«Локальные подложки карты»** можно скрыть или включить
всю панель. Кнопка **«Удалить подложку»** удаляет текущую подложку из кэша и библиотеки,
не затрагивая оригинал. Чтобы удалить другой набор, сначала выберите его в библиотеке.

Большие JPEG и TIFF подготавливаются отдельным процессом: исходное разрешение сохраняется,
на диске создаются тайловый GeoTIFF и уменьшенные уровни для общего вида. SHP
индексируются в SQLite; браузер получает только тайлы видимой области. DBF не
загружаются и не распаковываются: атрибуты не нужны для показа геометрии. Лимиты:
до 8 ГБ на загрузку, до 16 ГБ полезных файлов внутри ZIP. Перед подготовкой
проверяется свободное место на диске; для JPEG может понадобиться больше места,
чем занимает сжатый оригинал.

Прогресс и **«Отменить»** отображаются над картой. Отмена останавливает процесс и
удаляет незавершённые файлы текущего задания. Предыдущая подложка остаётся доступной,
если новый импорт завершился ошибкой. Исходные файлы не изменяются.

Готовые подложки хранятся в `%LOCALAPPDATA%\Signer\map_backgrounds` и доступны
после перезапуска в списке **«Ранее загруженные подложки…»**. Переключатели
**«Серверная / Локальная / Наложение»** сохраняют положение карты. В режиме наложения
доступна прозрачность; в **«Слои локальной подложки»** можно отключать отдельные SHP.
Кнопка **«К подложке»** показывает границы набора. Локальные тайлы можно увеличивать
до масштаба карты 24.

Если линии или полигоны SHP сведены к одной точке либо лежат вне области карты,
импорт сообщит об ошибке исходных координат. Для исправления нужен корректный экспорт
из исходной ГИС; увеличение лимита размера такую геометрию не восстанавливает.

Редактор ошибок находится в `ui/widgets/error_editor_page.py`. Выбор типа использует изображения из `sings/`; для отсутствующего изображения отображается текстовый пункт. После «Применить» запись помечается как проверенная, а «Сохранить» сохраняет `editor_reviewed: true` и изменения типа/текста в GeoJSON.

## Структура проекта

| Каталог | Назначение |
|---|---|
| `app/` | точка общих утилит, версия и проверка ресурсов |
| `configs/` | конфигурация обработки, знаков и пользовательских настроек |
| `core/` | детекция, GPS, геометрия и обработка знаков |
| `processing/` | контроллер и потоки обработки видео |
| `server/` | локальный Flask-сервер карты и медиасервисы |
| `ui/` | PyQt6-окна и страницы приложения |
| `templates/` | HTML/CSS/JavaScript карты |
| `licensing/` | проверка и обновление лицензии |
| `updater/` | установка обновлений |
| `scripts/build/` | подготовка, проверка и публикация релиза |
| `tests/` | регрессионные и интеграционные тесты |
| `docs/archive/` | исторические отчёты и устаревшие инструкции |

Модели и изображения знаков не следует считать Python-кодом: они поставляются отдельными ресурсами (`small_models/`, `CNN_side/`, `lane_guidance_models/`, `sings/`).

## Разработка и тесты

Запуск быстрых проверок:

```powershell
node tests/test_map_ui.js
.venv\Scripts\python.exe -m pytest tests/test_map_media.py tests/test_editor_inspection_and_recovery.py tests/test_editor_save_button.py -q
```

Перед изменением модели или пайплайна запускайте соответствующие тесты из `tests/`; полный набор может требовать PyQt6, OpenCV, ffmpeg и локальные тестовые ресурсы.

## Сборка и обновление

Актуальный сценарий подготовки — `scripts/build/prepare_release.bat`. Проверки артефактов находятся в `scripts/build/release_preflight.py`, `validate_release.py` и `test_release_artifacts.py`. Загрузка выполняется через `scripts/build/upload_release.bat` или `upload_release.ps1`.

Перед релизом проверьте версию в `version.json`, наличие моделей и файлов `installer/`. Не копируйте в релиз `.signer_clip_cache`, тестовые данные и временные каталоги.

Обновление устанавливается поверх существующей папки приложения; пользовательские лицензия и настройки должны находиться вне каталога сборки. Если автоматический updater не может заменить файлы, используйте полный установщик соответствующего выпуска.

## Лицензирование

Клиентская логика находится в `licensing/`. Проверка выполняется асинхронно и повторяет сетевой запрос при временных ошибках. Адрес сервера и число попыток задаются настройками приложения. Сервер лицензий — отдельный проект и не входит в клиентский запуск.

### Существующие знаки для сверки

На главной странице выберите GeoJSON в поле «Существующие знаки для сверки».
Файл должен содержать FeatureCollection в WGS84, геометрию Point или LineString
(положение знака — первая вершина) и properties.type. Итоговый файл выбирается отдельно.
После обработки совпадения проверяются по типу, радиусу и допуску азимута из настроек,
стороне дороги (left) и тексту знака. Азимуты в разных режимах не объединяются автоматически.
Однозначное совпадение подтверждает существующий знак, сохраняя его геометрию и атрибуты;
новое наблюдение хранится в comparison_observation. Новые знаки добавляются, незамеченные
в этом проезде сохраняются. Неоднозначные пары не удаляются: в редакторе они идут первыми
с предупреждением о возможном дубле. Исходный слой не изменяется.

Локальные подложки автоматически используют WebGL, если браузер и драйвер поддерживают его.
Все слои набора используют один графический контекст. При недоступности или потере WebGL
отображение возвращается к обычным тайлам, сохраняя выбранные слои. Режим показан в панели;
подсказка содержит название адаптера, если браузер разрешает его получить. Выбор встроенного
или дискретного адаптера выполняется браузером/ОС. Импорт, преобразование координат и
создание тайлов по-прежнему выполняются на CPU; индикатор WebGL относится к отображению.

Сверку можно выполнить без повторной обработки видео: выберите существующие знаки,
нажмите **«Сверить с обработанным GeoJSON…»**, выберите готовый результат и отдельный
выходной файл. Работа выполняется в фоне; итог автоматически открывается на карте
и доступен в редакторе. Оба исходных файла защищены от перезаписи.
В карточке выбранного знака на карте кнопка **«Открыть в редакторе знаков»** выбирает
соответствующую строку редактора. Для обратного перехода остаётся «Показать на карте».
