# Анализ совместимости автообновлений: v2.0.0 → v2.0.1

## Вопрос
После сборки нового релиза v2.0.1, система обновлений на старой версии v2.0.0 сработает корректно?

## Краткий ответ
**✅ ДА, система автообновлений сработает корректно.**

## Подробный анализ

### Что изменилось в v2.0.1

#### 1. Изменения в зависимостях (requirements.txt)
**Добавлены:**
- `onnx>=1.22.0`
- `onnxruntime>=1.29.0`
- `openvino>=2024.0`

**Влияние на автообновление:** ✅ **НЕТ**
- Зависимости устанавливаются при разработке, не в собранном .exe
- Собранный `Signer.exe` содержит все библиотеки внутри (PyInstaller)
- Пользователю не нужно устанавливать зависимости вручную

#### 2. Новые файлы моделей
**Добавлены:**
- `.onnx` файлы в `CNN_side/`, `lane_guidance_models/`, `small_models/`
- `*_openvino_model/` папки с `.xml` и `.bin` файлами

**Влияние на автообновление:** ✅ **НЕТ (с нюансом)**
- PyInstaller (`signer.spec`) включает все эти файлы в сборку через `datas`
- Архив `Signer.7z.*` будет содержать все новые модели
- При распаковке они окажутся в правильных папках

**Нюанс:** Размер архива увеличится (примерно на 200-500 MB из-за ONNX/OpenVINO моделей)
- Пользователю придётся скачать больше данных
- Это НЕ ломает автообновление, просто дольше качается

#### 3. Новые скрипты
**Добавлены:**
- `scripts/export_models_onnx.py`
- `scripts/build/verify_cpu_backends.py`

**Влияние на автообновление:** ✅ **НЕТ**
- Эти скрипты используются только при сборке релиза
- НЕ включаются в `Signer.exe` (не в `signer.spec`)
- Пользователь их не видит и не использует

#### 4. Новая документация
**Добавлены/обновлены:**
- `docs/BUILD_CPU_BACKENDS.md`
- `docs/RELEASE.md`
- `docs/RELEASE_v2.0.1_REPORT.md`

**Влияние на автообновление:** ✅ **НЕТ**
- Документация не включается в `Signer.exe`
- Пользователь её не получает через автообновление
- Только разработчики видят эти файлы в репозитории

#### 5. Обновления в signer.spec и prepare_release.bat
**Изменены:**
- `signer.spec` - добавлены проверки CPU-бэкендов
- `scripts/build/prepare_release.bat` - добавлены шаги экспорта/верификации

**Влияние на автообновление:** ✅ **НЕТ**
- Эти файлы используются только при сборке
- НЕ влияют на формат архива `Signer.7z.*`
- НЕ меняют структуру установки

    """Парсит версию вида "2.0.0" или "v2.0.0" в кортеж (2, 0, 0)."""
    clean = version_str.lstrip("v").strip()
    return tuple(int(x) for x in clean.split("."))

# Сравнение

    # Обновление доступно!

**✅ ДА**

- `updater.py` умеет проверять чексуммы

- Формат архива не изменился

#### Может ли v2.0.1 работать после обновления с v2.0.0?
**✅ ДА**
- Все новые файлы (`.onnx`, `*_openvino_model/`) будут распакованы в правильные места
- `Signer.exe` (v2.0.1) умеет работать с этими файлами

**✅ ДА**
- Настройки хранятся в реестре Windows (`QSettings`)
- История обработанных видео может храниться в `AppData` (если есть)
- Файлы пользователя (видео, GPS-треки) не трогаются

### Потенциальные проблемы

#### 1. Увеличенный размер архива
**Проблема:** Архив v2.0.1 будет больше на 200-500 MB из-за ONNX/OpenVINO моделей.

**Влияние:**
- Скачивание займёт больше времени
- Требуется больше места на диске во временной папке

**Решение:**
- ✅ Автоматически решено: `updater.py` показывает прогресс скачивания
- ✅ Автоматически решено: `updater.py` поддерживает докачку (resume) при обрыве

**Критичность:** 🟡 Незначительная (просто дольше качается)

#### 2. Пользователь не знает о новых CPU-бэкендах
**Проблема:** После обновления пользователь по-прежнему будет использовать PyTorch (старая настройка).

**Влияние:**
- Пользователь не получит улучшение производительности автоматически
- Нужно вручную зайти в Settings → Performance и выбрать ONNX/OpenVINO

**Решение:**
- ✅ Можно добавить уведомление в UI после первого запуска v2.0.1
- ✅ Можно добавить в release notes информацию о новых бэкендах

**Критичность:** 🟡 Незначительная (не ломает функциональность)

#### 3. Delta-updates НЕ поддерживаются для v2.0.0 → v2.0.1
**Проблема:** Дельта-обновления (файл `delta-from-2.0.0.zip`) не создаются автоматически.

**Влияние:**
- Пользователь скачает полный архив (~1-2 GB вместо ~500 MB дельты)

**Решение:**
- Можно вручную создать дельта-обновление через `scripts/build/create_delta.py`
- Или оставить полное обновление (проще для первого релиза v2.0.1)

**Критичность:** 🟡 Незначительная (дельта - опция, не обязательность)
