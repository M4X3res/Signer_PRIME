# Video Player Streaming Fix

**Дата:** 2026-09-04  
**Проблема:** Timeout при загрузке больших видео в браузере на карте

---

## 1. Исправленная проблема — некорректный парсинг HTTP Range

### Баг

`server/map_server.py::api_video()` некорректно обрабатывал **suffix-byte-range-spec**:

```python
# БЫЛО (неправильно):
byte_range = range_header.replace('bytes=', '').split('-')
start = int(byte_range[0]) if byte_range[0] else 0  # ← БАГ: пустая строка → 0
```

HTTP-спецификация (RFC 7233): заголовок `Range: bytes=-N` означает **последние N байт файла**.
Код трактовал это как "с начала", что критично для видео без `+faststart` (атом `moov` в конце файла).

### Исправление

Теперь корректно поддерживаются все три формы:
- `bytes=start-end` — диапазон
- `bytes=start-` — от start до конца
- `bytes=-suffix` — последние suffix байт (для поиска `moov` в конце файла)

Также:
- Увеличен лимит чанка с 10 МБ до 50 МБ (меньше round-trip'ов)
- Используется `.set()` вместо `.add()` для предотвращения дублирования заголовков
- Добавлен `conditional=False` в fallback-ветке `send_file()`

## 2. Рекомендация — `+faststart` для ускорения загрузки

Если видео "тормозит" при первой загрузке метаданных (даже после фикса Range), можно ускорить это,
предварительно переместив атом `moov` в начало файла:

```bash
ffmpeg -i input.mp4 -c copy -movflags +faststart output.mp4
```

**Что это делает:**
- Копирует видео/аудио потоки без перекодирования (`-c copy` — быстро)
- Перемещает метаданные (`moov`) из конца файла в начало
- Браузер сразу получает информацию о длительности/кодеках без скачивания конца файла

**Когда это критично:**
- Файлы > 1 ГБ
- Медленная сеть или сетевое хранилище
- Видео с GoPro без постобработки (по умолчанию `moov` в конце)

**Когда это НЕ обязательно:**
- Range-фикс выше **уже решает проблему** функционально (видео загружается)
- `+faststart` — оптимизация UX (быстрее первая загрузка), а не требование

## 3. Тестирование

### Проверка suffix-range вручную:

```bash
# Запросить последние 1024 байта файла
curl -v -H "Range: bytes=-1024" http://127.0.0.1:3000/api/video/0 > last_1024.bin

# Сравнить с реальным концом файла
tail -c 1024 path/to/video.mp4 > expected_1024.bin
diff last_1024.bin expected_1024.bin
# Должно быть пусто (файлы идентичны)
```

### Проверка в браузере:

1. Открыть карту, выбрать знак с видео > 1 ГБ
2. DevTools → Network → найти `/api/video/<idx>`
3. Проверить:
   - Статус `206 Partial Content`
   - **Один** заголовок `Content-Range` (не два!)
   - **Один** заголовок `Content-Length`
   - При suffix-range: `Content-Range: bytes X-Y/Z` где X близко к Z (конец файла)
4. Убедиться что `loadedmetadata` срабатывает (не timeout)
5. Перемотка (`video.currentTime = seconds`) работает без зависания
