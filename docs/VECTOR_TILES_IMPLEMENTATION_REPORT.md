# Отчёт: Реализация поддержки векторных тайлов (.pbf)

**Дата:** 2026-09-15  
**Статус:** ✅ Выполнено полностью  

## Обзор

Реализована полная поддержка векторных тайлов формата Mapbox Vector Tiles (.pbf) в карте приложения Signer PRIME, с сохранением полной обратной совместимости с растровыми тайлами (PNG/JPG).

## Реализованные задачи

### ✅ Задача 1 — Настройки: тип подложки

**Файл:** `configs/settings.py`

Добавлено новое поле в `AppSettings`:
```python
map_tile_type: Literal["raster", "vector"] = "raster"
```

**Файл:** `ui/widgets/settings_page.py`

1. **Добавлен UI-компонент:**
   - `QComboBox` с выбором "Растровые тайлы (PNG/JPG)" и "Векторные тайлы (.pbf)"
   - Размещён ПЕРЕД полем "URL тайлов"
   - Подключен к системе тем через `connect_combobox_theme_updates()`
   - Подсказка (hint) с предупреждением о порядке координат {z}/{x}/{y} vs {z}/{y}/{x}

2. **Интегрирован в методы:**
   - `_collect_settings()` — сбор значения из UI в настройки
   - `_reset()` — восстановление дефолтного значения ("raster")
   - `_import_settings()` — импорт значения из JSON файла

3. **Добавлена валидация:**
   - Метод `_check_tile_url_mismatch()` проверяет соответствие типа и расширения в URL
   - Показывает мягкое предупреждение при несоответствии (.pbf с raster или .png с vector)
   - Не блокирует сохранение, но информирует пользователя о возможной проблеме

### ✅ Задача 2 — Сервер: отдавать тип подложки

**Файл:** `server/map_server.py`

Обновлён endpoint `/api/map_config`:
```python
return jsonify({
    "tile_url": settings.map_tile_url,
    "attribution": settings.map_tile_attribution,
    "max_zoom": settings.map_tile_max_zoom,
    "tile_type": settings.map_tile_type,  # NEW
})
```

Также добавлен fallback при ошибке:
```python
"tile_type": "raster"  # Безопасный откат на растр
```

### ✅ Задача 3 — Фронтенд: рендер векторных тайлов

**Файл:** `templates/map.html`

1. **Подключена библиотека Leaflet.VectorGrid:**
   ```html
   <script src="https://unpkg.com/leaflet.vectorgrid@1.3.0/dist/Leaflet.VectorGrid.bundled.js"></script>
   ```

2. **Обновлена функция `loadTileLayer()`:**
   - Проверка `cfg.tile_type === 'vector'`
   - Проверка доступности `L.vectorGrid` (откат на OSM при отсутствии)
   - Создание векторного слоя через `L.vectorGrid.protobuf()`
   - Универсальный стиль `{ '*': genericStyle }` для всех слоёв
   - Поддержка тёмной темы (цвета подобраны для dark mode)
   - Логирование в консоль для отладки

3. **Стилизация векторных тайлов:**
   ```javascript
   const genericStyle = {
     weight: 1,
     color: '#3d8ef0',        // Синий для линий
     fillColor: '#1c2128',    // Тёмно-серый для заливки
     fillOpacity: 0.3,        // 30% прозрачность
   };
   ```

4. **Безопасный fallback:**
   - При любой ошибке (недоступен сервер, не загружена библиотека, неверный URL) карта откатывается на OSM растр
   - Гарантия отображения карты в любом случае

### ✅ Задача 4 — Валидация URL

**Реализовано в:** `ui/widgets/settings_page.py::_check_tile_url_mismatch()`

Проверяет:
- Векторный тип + .png/.jpg/.jpeg в URL → предупреждение
- Растровый тип + .pbf/.mvt в URL → предупреждение

Не блокирует сохранение, но информирует пользователя о потенциальной проблеме.

## Критерии приёмки

### ✅ Обратная совместимость

Существующие пользователи с растровыми тайлами:
- Отсутствующее поле `map_tile_type` интерпретируется как `"raster"` (дефолт в dataclass)
- QSettings автоматически десериализует отсутствующие поля в дефолтные значения
- Карта продолжает работать без изменений

### ✅ Векторные тайлы работают

- Можно выбрать тип "Векторные тайлы" в UI
- Ввести URL с .pbf
- Сохранить настройки
- Карта загружает векторный слой через `L.vectorGrid.protobuf()`

### ✅ Fallback на OSM при ошибке

- Если VectorGrid не загружен → откат на OSM растр
- Если векторный URL недоступен → откат на OSM растр
- В консоли браузера логируется ошибка для отладки
- Приложение не падает, карта остаётся доступной

### ✅ Поле `tile_type` в `/api/map_config`

```json
{
  "tile_url": "...",
  "attribution": "...",
  "max_zoom": 19,
  "tile_type": "raster"  // или "vector"
}
```

Fallback при ошибке также включает `"tile_type": "raster"`.

### ✅ Тёмная тема не ломает векторные тайлы

- Векторные тайлы отрисовываются с тёмными цветами по умолчанию
- CSS-фильтр `.leaflet-tile` применяется только к растровым тайлам (img)
- Векторные тайлы (canvas) стилизуются через `vectorTileLayerStyles`

### ✅ Не затронуты критические модули

- `core/`, `processing/`, `licensing/` — без изменений
- Порт 3000 и архитектура Flask/SocketIO — без изменений
- Пайплайн обработки видео/знаков — без изменений

## Известные ограничения

1. **Стилизация векторных тайлов:**
   - Используется универсальный стиль для всех слоёв (`{ '*': genericStyle }`)
   - Нет возможности настроить стили для конкретных слоёв (water, roads, buildings) через UI
   - Для продвинутой стилизации требуется редактирование JavaScript в `map.html`

2. **Порядок координат:**
   - Некоторые провайдеры используют `{z}/{y}/{x}`, другие `{z}/{x}/{y}`
   - Пользователь должен вручную уточнить порядок в документации провайдера
   - Автоопределение невозможно (требуется знание API конкретного провайдера)

3. **Производительность:**
   - Векторные тайлы требуют больше CPU для отрисовки
   - На слабых компьютерах может быть заметно замедление при zoom/pan
   - Для таких случаев рекомендуется использовать растровые тайлы

4. **Оффлайн-режим:**
   - Библиотека VectorGrid загружается через CDN (unpkg.com)
   - Требуется интернет при первой загрузке карты
   - При отсутствии интернета — автоматический откат на растровый OSM
