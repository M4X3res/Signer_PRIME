# CNN Кэширование

## Обзор

CNN кэширование — это система хранения результатов классификации знаков в памяти для ускорения повторных распознаваний. Использует LRU (Least Recently Used) алгоритм для управления памятью.

## Преимущества

✅ **Ускорение на 30-50%** при типичных сценариях  
✅ **Без потери точности** — кэшируются реальные результаты моделей  
✅ **Автоматическое управление памятью** — LRU вытеснение старых записей  
✅ **Настраиваемый размер** — от 100 до 5000 записей  

## Как это работает

### 1. Хэширование изображений

Для каждого crop'а знака 32x32 вычисляется быстрый хэш:

```python
# Приоритет: xxHash (быстрее) → MD5 (fallback)
hash = xxhash.xxh64(image.tobytes()).hexdigest()[:16]
```

### 2. Ключ кэша

Ключ состоит из категории YOLO + хэш изображения:

```
"treugolnik:a3f2c8d9e1b4567a"
"krugH:9c8e7d6f5a4b3210"
```

Это позволяет:
- Различать одинаковые изображения в разных категориях
- Быстро проверять наличие в кэше (O(1))

### 3. LRU вытеснение

При превышении лимита удаляется самая старая запись:

```python
if len(cache) > maxsize:
    cache.popitem(last=False)  # удалить первый (самый старый)
```

### 4. Кэширование субмоделей

Для треугольников с субклассификацией кэшируются оба уровня:

```python
cache["treugolnik:hash1"] = ("1.21", 0.85)
cache["sub_1.21:hash1"] = ("1.21", 0.92)
```

## Алгоритм

```python
def classify_with_cache(image_32x32, yolo_class):
    # 1. Вычислить хэш
    hash = compute_hash(image_32x32)
    key = f"{yolo_class}:{hash}"
    
    # 2. Проверить кэш
    if key in cache:
        return cache[key]  # HIT — мгновенный возврат
    
    # 3. MISS — запустить CNN модель
    result = cnn_model.predict(image_32x32)
    
    # 4. Сохранить в кэш
    cache[key] = result
    
    return result
```

### Почему работает?

1. **Трекинг знаков** — один знак виден 4-10 кадров подряд
2. **Похожие знаки** — много одинаковых знаков (например, ограничения скорости)
3. **Повторы в видео** — при возврате на одну дорогу

### Потребление памяти

```python
Одна запись кэша ≈ 100 байт (хэш + результат + служебная информация)
Размер кэша 1000 = ~100 КБ
Размер кэша 5000 = ~500 КБ
```

**Вывод:** Память незначительна по сравнению с моделями (несколько ГБ).

## Когда НЕ эффективно

❌ **Единичный проход по новому маршруту** — каждый знак уникальный  
❌ **Очень высокая скорость движения** — знаки видны 1-2 кадра  
❌ **Маленький размер кэша** — постоянное вытеснение  

В этих случаях overhead хэширования может превысить выигрыш (но всё равно < 5% потерь).

## Детали реализации

### Класс CNNCache

```python
class CNNCache:
    def __init__(self, maxsize: int = 1000):
        self._cache: OrderedDict = OrderedDict()  # сохраняет порядок вставки
        self._maxsize = maxsize
        self._hits = 0
        self._misses = 0
    
    def get(self, key: str) -> Optional[tuple[str, float]]:
        if key in self._cache:
            self._hits += 1
            self._cache.move_to_end(key)  # обновить позицию (LRU)
            return self._cache[key]
        
        self._misses += 1
        return None
    
    def put(self, key: str, value: tuple[str, float]) -> None:
        self._cache[key] = value
        self._cache.move_to_end(key)
        
        if len(self._cache) > self._maxsize:
            self._cache.popitem(last=False)  # удалить первый
```

### Хэширование

**xxHash (предпочтительно):**
```python
import xxhash
hash = xxhash.xxh64(img.tobytes()).hexdigest()[:16]
```

**MD5 (fallback если xxhash не установлен):**
```python
import hashlib
hash = hashlib.md5(img.tobytes()).hexdigest()[:16]
```

**Производительность:**
- xxHash: ~1-2 µs на изображение 32x32
- MD5: ~5-10 µs на изображение 32x32

**Зачем обрезаем до 16 символов?**
- Полный хэш избыточен (128 бит для MD5, 64 бит для xxHash)
- 16 символов = 64 бита — достаточно для 32x32 изображений (коллизии практически невозможны)

## Комбинация с умным frame skipping

Два механизма работают синергично:

1. **Smart Skipping** — пропускает кадры → меньше детекций
2. **CNN Cache** — ускоряет оставшиеся детекции

**Суммарный эффект:**

```
Базовая скорость:    5 FPS
+ Smart Skipping:   15 FPS (3x ускорение)
+ CNN Cache:        22 FPS (4.4x ускорение от базы)
```

## Тестирование

### Unit-тест кэша

```python
def test_cnn_cache():
    cache = CNNCache(maxsize=3)
    
    # Добавление
    cache.put("key1", ("3.24", 0.85))
    cache.put("key2", ("1.21", 0.92))
    cache.put("key3", ("2.1", 0.78))
    
    assert cache.size == 3
    
    # Попадание
    result = cache.get("key1")
    assert result == ("3.24", 0.85)
    assert cache.hit_rate == 100.0
    
    # Промах
    result = cache.get("key999")
    assert result is None
    assert cache.hit_rate == 50.0  # 1 hit, 1 miss
    
    # LRU вытеснение
    cache.put("key4", ("5.16", 0.88))
    assert cache.size == 3  # key2 должен быть вытеснен
    assert cache.get("key2") is None
```

### E2E тест

```python
def test_detector_with_cache():
    detector = Detector()
    
    # Загружаем тестовый знак
    img = cv2.imread("test_sign_3.24.png")
    
    # Первое распознавание (MISS)
    start = time.time()
    result1 = detector.detect(img)
    time1 = time.time() - start
    
    # Второе распознавание (HIT)
    start = time.time()
    result2 = detector.detect(img)
    time2 = time.time() - start
    
    # Результаты должны совпадать
    assert result1 == result2
    
    # Второй раз должен быть быстрее
    assert time2 < time1 * 0.5  # минимум 2x быстрее
    
    # Hit rate должен быть 50%
    assert detector.cache_hit_rate == 50.0
```

## FAQ

**Q: Влияет ли на точность?**  
A: Нет, кэшируются реальные результаты моделей.

**Q: Сколько памяти потребляет?**  
A: ~100 байт на запись. Для 1000 записей = ~100 КБ (ничтожно).

**Q: Работает ли между видео?**  
A: Да, кэш сохраняется внутри одной сессии обработки.

**Q: Что если изображения слегка отличаются (сжатие, шум)?**  
A: Хэш изменится → MISS. Это нормально и ожидаемо.

**Q: Можно ли кэшировать YOLO результаты?**  
A: Нет, YOLO работает на полном кадре. Кэш эффективен только для crop'ов.

**Q: Нужно ли устанавливать xxhash?**  
A: Нет, но рекомендуется для лучшей производительности (2x быстрее хэширования).
